# p047 新邮件收取时延排查、调度优先级翻转与场景化同步规范

- 来源：用户提出
- 内容：
    1. 现状与链路分析：
        - 用户反馈新邮件到达客户端感知耗时过长；
        - 链路划分：【后端 → 前端】已通过 PostgreSQL LISTEN/NOTIFY + SSE 实时推送（150ms 节流），无延迟；瓶颈完全在于【外部邮件服务器 → 后端拉取】段。
    2. 核心根因：
        - 任务调度权重严重倒挂：`src/mail_core/sync/jobs.py` 中优先级为数值越小越优先（`order_by(WorkerJob.priority.asc())`），目前重型的批量正文/附件下载 `ARCHIVE_MIME_BATCH` 权重为 `40`，而轻量增量新邮件拉取 `SYNC_FOLDER_DELTA` 权重为 `60` / `75`，导致轻量增量扫描被大附件归档长期堵在队尾（队头拥塞）；
        - 前端视线与后台拉取脱节：用户窗口聚焦或切账号时不触发同步，仅查本地数据库，若恰逢 30 秒轮询间隔初段必须白等近 30 秒；
        - 缺少各同步场景的严格区分，无多账号冷热分级调度与并发连接池防护。
    3. 同步场景与职责清晰划分规范：
        - **新账号加入/接入**：触发**全量同步（Full Sync）**，执行 `SYNC_ACCOUNT_FOLDERS`（优先级 50），完整拉取目录树与初始化元数据；
        - **日常后台轮询**：执行轻量**增量同步（Delta Sync）**，执行 `SYNC_FOLDER_DELTA`，前台活跃收件箱自适应缩短至 5~10 秒；
        - **前端窗口聚焦（`window.onfocus`）与账号切换**：触发当前激活账号收件箱轻量**增量同步**，附带 10~15 秒防抖冷却，秒级感知新邮件；
        - **邮件列表右上角手动同步按钮**：触发当前激活收件箱轻量**增量同步**；
        - **设置界面手动同步**：仅在“设置”提供**全量同步**（单账号/全部账号重新扫描全部文件夹及状态）；
        - **正文与附件归档**：作为后台低优任务异步完成，不阻塞元数据与新邮件发现。
    4. 任务权重翻转实施方案：
        - `SYNC_FOLDER_DELTA`（增量新邮件发现）：优先级调整为高优（数值 **`20`**）；
        - `ARCHIVE_MIME_BATCH`（批量大文件/正文归档）：优先级降为后台低优（数值 **`75` ~ `80`**）；
        - 多账号调度防护：引入全局外部连接池并发限流（上限 8~16），在全部收件箱下仅对 Hot 活跃账号（前 3~5 个）做前台聚焦拉取，彻底规避千级账号风控与雪崩。
