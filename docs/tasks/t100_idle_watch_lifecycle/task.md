# Task spec

## 背景

p105 引用 t096 审阅中的 IDLE 模块拆解建议。基于 `060e0893`，`idle_watcher.py` 已有 885 行，同时承担候选排序、席位管理、会话重连与补偿、线程和 reader 关闭、状态发布。关闭中资源分布在多个集合，周期对账与停止路径需要共同维护配额和身份约束。

## 契约区

### 范围

- 提取无 I/O 的席位策略。单账号会话单独拥有连接、续订、重连、通知及有界补偿。管理器集中拥有席位分配、关闭中资源与状态发布。
- 以 watch 实例归属约束状态提交和席位释放。区分资源仍占席位与订阅有效，后者决定收件箱轮询何时兜底。
- 保留现有收件箱资格、后台增量去重键及 IDLE 主链路行为，清除被替换的实现和内部转发层。

### 非范围

- 全夹巡检状态、IMAP 协议协商逻辑、账号连接健康契约及 Worker 全局任务槽位。

### 验收标准

- [x] AC-001：候选席位沿用邮件到达时间、空收件箱分组和稳定次序。滞回只保护同组可比较候选。凭据轮换或收件箱失去资格时关闭对应订阅。
- [x] AC-002：活动和关闭中的 watch 都受同一配额约束。旧 watch 的执行线程与其 reader 均退出后才可转让席位。慢关闭、挂起 reader 和重复对账期间，每账号有效订阅至多一条，全局席位不超配。迟到状态不覆盖新 watch。

- [x] AC-004：健康订阅聚合状态与轮询跳过集合相符。处于退避或关闭中的 watch 即使仍占资源席位，也允许该账号恢复轮询。Worker 停止后不再接纳新 watch。

### 风险与回退

- 风险：关闭中线程可能提前释放席位、阻塞健康账号或使轮询错误停用。用受控慢连接、慢关闭与交替对账验证。
- 回退：回退实现 commit 恢复旧管理器，重启 Worker 以重建进程内 IDLE 会话，本次不涉及 schema。
