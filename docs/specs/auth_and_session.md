# 用户认证与会话生命周期技术规范 (Auth and Session Specification)

本文档定义 kkmail 的密码鉴权、持久化存储、签名会话机制、CSRF 防护与防爆破限流技术规范。

______________________________________________________________________

## 一、 鉴权架构与凭据持久化

kkmail 采用自托管单用户安全架构，以数据库中的持久化凭据作为权威身份源：

1. **密码存储与散列算法**：
    - 用户密码经 `bcrypt` 强哈希（带安全盐）存储于 PostgreSQL `auth_credentials` 表（主键 `id = 'default'`）；
    - 系统严禁在配置文件、日志或进程内存中明文保留管理密码。
2. **初始化与修改流程**：
    - 首次启动若数据库无凭据记录，支持从配置/环境变量引导初始密码哈希，入库后以数据库为唯一基线；
    - 密码修改接口执行原子事务更新：持久化新密码哈希同时递增 `session_epoch` 版本号，写库失败则 Fail-Closed 拒绝改密。

## 二、 会话管理与 Session Epoch 吊销机制

系统支持基于签名 Cookie 的 Web/桌面交互会话，以及面向自动化的 Bearer API Key 认证：

### 1. 签名 Cookie 会话与 Epoch 校验

- **Cookie 结构**：登录成功后签发 `kkmail_mc_session` Cookie，载荷包含会话标识与签发时的 `session_epoch`，由应用主密钥 HMAC 签名。
- **全局会话吊销机制 (Session Epoch)**：
    - 数据库 `auth_credentials.session_epoch` 为全局会话有效性代际计数器；
    - 发生改密、显式注销或重置凭据时，`session_epoch` 单调递增；
    - 每次收到请求时校验 Cookie 中的 epoch 是否与当前数据库/缓存代际匹配；若低于当前代际，该会话立即作废。
- **时效与缓存策略**：
    - 为避免高频请求击穿数据库，服务各工作进程本地缓存 `session_epoch`（TTL 5 秒）；
    - 当前进程内触发改密或注销时，数据库事务提交后立即清除本进程缓存；跨进程节点最长 5 秒内全网失效。过期或数据库不可达时 Fail-Closed。

### 2. Bearer API Key 机制

- 服务端配置 `MAIL_CORE_API_KEYS` 时启用 API Key 认证；
- 客户端请求头携带 `Authorization: Bearer <API_KEY>`；API Key 验证通过后豁免 Session Cookie 与 CSRF 校验。

## 三、 防御与安全约束

1. **CSRF 跨站请求伪造防护**：
    - 登录成功返回与当前会话绑定的安全随机 `csrf_token`；
    - 所有基于 Cookie 会话的非幂等写操作（`POST`、`PUT`、`PATCH`、`DELETE`）必须在请求头携带 `X-CSRF-Token`；
    - 缺失或校验不匹配时一律返回 HTTP 403 拒绝执行。
2. **防暴力破解与登录速率限制**：
    - 基于客户端 IP 与用户标识实施滑动窗口速率限制；
    - 同一客户端在 300 秒内连续认证失败达 10 次触发熔断，接口返回 HTTP 429 Too Many Requests 并携带标准 `Retry-After` 响应头；
    - 登录失败记录设有全局容量上限，防止未认证恶意请求耗尽内存状态表。
