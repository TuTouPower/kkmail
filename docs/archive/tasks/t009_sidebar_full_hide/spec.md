# Task spec

## 背景

p014 要求侧栏折叠后完全释放横向空间，将展开入口放在列表标题左侧。workspaceLayout 当前为折叠侧栏保留 48px，App 始终渲染 Sidebar，CSS 隐藏内容但保留窄轨；既有有效 spec AC-006 仍要求折叠至图标栏，交付时须改为完全隐藏语义。

## 契约区

### 范围

- 桌面折叠侧栏不再占网格轨与分割条；更新 grid 子节点和列宽计算。
- 列表标题左侧展开入口、恢复侧栏及既有宽度；设置页打开时仍可恢复导航。
- 移动端导航抽屉与桌面折叠状态保持清晰独立；断点来回切换可恢复导航。

### 非范围

- 不改文件夹内容、主题配色、账号图标偏好或侧栏宽度约束。
- 不新增折叠状态持久化或重写整个布局系统。

- [ ] AC-001：桌面折叠后，侧栏及其分割条不再占宽或可聚焦，列表与阅读区仍在同一行；折叠前 48px 窄轨和对应网格列消失，列表获得释放空间。
- [ ] AC-002：桌面折叠时，列表顶部标题文字左侧出现可键盘操作、有明确展开名称的按钮；点击恢复侧栏和原已保存宽度，邮件选择、列表范围与阅读内容保持不变，展开后按钮不重复占位。
- [ ] AC-003：折叠状态打开设置时，设置内容占满剩余区域且仍提供可访问展开入口；关闭设置返回列表后展开按钮可用，展开/折叠不造成网格换行或空白轨。
- [ ] AC-004：移动端通过列表标题左侧导航按钮打开抽屉，关闭按钮、ESC 与遮罩仍正常关闭；桌面折叠状态不阻止移动端打开导航，跨越 760px 断点后导航、列表和阅读区保持可访问，无孤立按钮轨。
- [ ] AC-005：侧栏展开时原侧栏拖拽调宽与列表拖拽调宽仍有效；折叠时列表分割条正常工作，侧栏宽度值不被覆盖为零，设置与阅读模式实际子节点数始终匹配网格轨。

### 有意不测

### 测试策略

- workspaceLayout 测试覆盖 wide/narrow × 折叠/展开 × 设置/邮件，断言实际轨数与渲染子节点一致，折叠不保留侧栏轨。
- App、MessageList、SettingsModal 组件交互测试覆盖恢复入口、保持选择/宽度及无隐藏焦点陷阱。
- 浏览器布局测试测量折叠侧栏宽度/列表起点，验证标题前按钮、拖拽调宽、设置切换与 760px 断点两侧抽屉。

### 风险与回退

- 风险：只改列宽不改实际子节点会引发换行；隐藏侧栏仍可聚焦会破坏键盘导航；移动抽屉若复用桌面折叠条件会被永久隐藏。
- 回退：回退执行 commit 恢复原窄轨；保留现有本地宽度偏好，无数据迁移。
