# Task spec

## 背景

v3 要求直接拖动账号行与分组行，不占用拖动手柄。总列表展示所有账号，因此必须区分“总列表内排序”和“从组拖回总列表移出组”，不能依据账号当前 group_id 推断拖动目的。

## 契约区

### 范围

- 整行拖拽分组排序、账号总列表/组内排序、账号移入/跨组/移出。
- 接入 t027 持久排序与 t030 统一组织命令，提供目标反馈、失败恢复和恢复默认排序。

### 非范围

- 不引入远端文件夹或邮件拖动、不做多选账号拖动、嵌套组或多组归属。
- 不强制手机触摸拖动；窄屏使用 t030 账号归属选择完成相同移动结果。

### 验收标准

<!-- 规范（门禁必留，不得删除） -->

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：账号与分组从整行即可开始拖动，没有专门手柄图标；点击展开箭头、菜单或普通行点击不误触移动；可放置目标有反馈，结束/取消后反馈清除。
- [ ] AC-002：从总列表拖账号到空组、折叠组或有成员组可加入目标组；从 A 组拖至 B 组可移组；拖到目标账号行时插入该账号之前，放到组标题/空区时追加末尾；两处账号引用仍对应同一账号。
- [ ] AC-003：从组内拖到账号列表标题、空区或总列表账号行会移出原组，账号与邮件保留；放到总列表账号行前会同时定位总列表顺序。
- [ ] AC-004：从总列表拖到同一总列表只改变总列表顺序，即使该账号已有分组也保持归属；组内重排只改变该组账号顺序；拖动来源上下文参与判定，不能照搬 demo 通过 groupId 自动清组的逻辑。
- [ ] AC-005：分组整行可调整分组先后，所有账号与账号列表固定位置不可拖动；同一列表内账号调整后启用该列表手动排序，刷新及新会话读取仍保留，组与总列表相互独立。
- [ ] AC-006：恢复默认排序使总列表及所有组内账号重新按域名再完整邮箱升序；分组先后与成员关系不变；明确显示保存错误，失败后恢复服务端事实而非仅 toast 成功。
- [ ] AC-007：拖到自身、无效目标、取消、未知外部载荷均不改变状态；持久化失败不留下半移组/半排序；同一页面连拖不会让旧响应覆盖新结果，组成员变化触发组邮件范围从首屏重查。

### 有意不测

- demo 的发信、回复、转发与归档动作：不属本次侧栏改造及项目当前产品范围。

### 测试策略

- 组件/命令测试覆盖来源上下文与目标矩阵、失败回滚、顺序独立性和恢复默认。
- 真实浏览器拖动空/折叠/有成员组、总列表标题及账号行，再刷新检查后端持久结果；覆盖有分组账号在总列表内部重排这一回归场景。运行前端门禁与全栈 E2E。

### 风险与回退

- 风险：事件冒泡误判目标或来源，排序同时解除归属；旧响应导致 UI 回退到旧顺序。
- 回退：回退本 task 执行提交；保留服务端组织数据和 t030 非拖动操作入口。

### 依赖与约束

- 依赖 t030，复用其组织命令及 t027 原子接口；依赖树已包含 t029。
- 优先使用项目现有浏览器能力，不为单次拖动引入通用布局/拖放框架。
- 新 UI 引用遵守稳定编号规则，拖动反馈色使用 tokens。
