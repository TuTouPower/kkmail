# 账号导航控制、读状态同步与地址交互技术规范 (Account Navigation & Read State Specification)

本文档定义 kkmail 账号启闭控制、多目录已读状态同步、侧栏局部过滤及邮箱地址交互复制技术规范。

______________________________________________________________________

## 一、 账号启闭状态与聚合视图隔离

1. **禁用账号显示与聚合过滤**：
    - 处于 `sync_enabled=false` 的账号从侧栏导航、全局聚合分类及各分组列表中隐藏，设置页中保持可见并可重新启用；
    - 全局与分组聚合接口（`/api/mail/inbox`、`/api/mail/search`、`/api/mail/stats` 以及批量已读）严格排除禁用账号的邮件与统计；空账号聚合返回空结果与零统计；
    - 显式通过 `account_id` 或 `folder_id` 直达的单账号/单目录查询保持可用。
2. **布局与状态保护**：
    - 账号禁用仅影响展示过滤，不破坏服务端持久化的侧栏分组归属、成员关系或排序快照；重新启用后自动恢复原有位置；
    - 当前正在浏览的账号若被禁用，界面自动重置导航并返回全局收件箱。

## 二、 邮件多位置归属与读状态即时同步

1. **多文件夹位置归属 DTO**：
    - 列表与搜索响应项携带该邮件在所属账号内的全部位置集合 `locations: [{folder_id, role}]`；
    - 客户端依据 `locations` 精确更新同账号内关联文件夹的已读/未读统计缓存，杜绝按当前视图名称盲目猜测。
2. **读状态乐观更新与写排序**：
    - 读/未读状态变更在前端按 `mailKey` 去重并立即执行乐观更新，逐文件夹增减匹配计数；未知状态（`null`）保持原样；
    - 针对同一邮件的连续状态变更请求强制串行化执行；本地写操作期间合并并延后收件箱及统计的 SSE 失效通知，待操作全部完成后再拉取权威数据对账；
    - 批量标记已读与单封状态操作互斥排序，失败时精确回滚受影响变更并刷新服务端事实。

## 三、 侧栏账号局部即时搜索

1. **独立过滤与匹配规则**：
    - 自定义分组与总账号列表分别维护各自的本地搜索词；
    - 过滤条件按邮箱地址、域名、显示名称及别名执行大小写不敏感匹配；禁用账号不参与搜索；
    - 搜索仅在组件本地内存生效，不持久化至用户偏好，关闭搜索立即清空并恢复原展开树。
2. **操作约束**：
    - 搜索过滤仅改变侧栏账号入口的展示过滤，不修改邮件 Scope、分组实际成员或邮件总数；
    - 过滤处于激活状态期间，禁用账号与分组的拖放排序，防止产生局部半份布局提交。

## 四、 邮件地址结构化解析与安全复制

1. **地址结构化数据契约**：
    - 邮件详情响应在保留原始 `to`、`cc` 展示字符串的同时，返回必需的结构化数组 `to_addresses` 与 `cc_addresses`；
    - 规范项包含 `{name: string, address: string | null, text?: string}`；
    - 经标准邮件地址解析器提取出的合法地址填充 `address`；无法可靠解析的残缺片段保留在 `text` 字段且 `address` 置为 `null`。
2. **安全复制交互契约**：
    - 阅读器发件人、收件人/抄送人、侧栏账号行及设置页地址使用标准复制控件；不可靠解析项（`address === null`）仅展示文本，不提供复制入口；
    - 普通地址文本点击即复制；已有导航或展开动作的行采用独立兄弟图标按钮触发复制；
    - 复制纯地址成功后提供约 2 秒视觉反馈，连续点击重置计时，组件卸载时安全清理定时器；
    - 复制统一调用标准 `navigator.clipboard.writeText`，邮件正文 iframe 无剪贴板写入权限，全局严禁申请剪贴板读取能力。
