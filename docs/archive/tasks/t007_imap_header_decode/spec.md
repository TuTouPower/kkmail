# Task spec

## 背景

p011 报告历史邮件主题与发件人乱码。当前 IMAP 入口先以 UTF-8 replace 解码整个报头，裸 GBK 字节在 MIME 字段解析前已经不可逆损坏；\_decode_header 对无 charset 字节也只按 UTF-8 replace 处理。

## 契约区

### 范围

- IMAP 元数据扫描与增量路径共用解析入口中的 Subject、From、To、Cc 字节保真解码。
- 定义确定性兼容策略：优先遵守有效 RFC 2047 charset；无声明字节优先严格 UTF-8，再尝试 GB18030 兼容 GBK/GB2312；无法恢复时才有损替换。
- 验证修复后的元数据经现有重取/应用路径更新旧记录及搜索索引，不增加自动历史回填任务。

### 非范围

- 不重写 MIME 正文/附件解析，不按语言猜测任意字符集，不引入通用字符集检测服务。
- 不从已经写入的替换符反推原字节；不自动重置全部账号同步游标或批量重扫生产邮箱。
- 不改变 Gmail/Graph JSON 报头解析。

### 风险与回退

- 风险：无声明报头存在编码歧义；过早全局解码可污染 RFC 2047 混合字段。已丢失原字节的记录不能仅靠前端修复。
- 回退：回退执行 commit 恢复解析逻辑；本 task 不自动修改生产历史数据。任何后续人工重取须保留备份和现有邮件身份。
