# 邮件增量同步、MIME解析与分块加密存储技术规范 (Mail Sync, Parsing & Storage Specification)

本文档定义 kkmail 多协议邮件同步引擎、Worker 任务调度、MIME 归档解析、安全删除阻断与分块内容寻址加密存储技术规范。

______________________________________________________________________

## 一、 协议同步引擎与状态流转

系统支持从标准 IMAP 服务与 Microsoft Graph API 持续增量同步邮件元数据：

### 1. IMAP 协议同步与异常容错

- **连接与安全性**：强制开启 TLS 证书与主机名校验，Socket 读取默认超时放宽至 60 秒；mailbox 文件夹包含空格或特殊字符时自动带双引号转义。
- **目录发现与 RFC 6154 属性映射**：
    - 标准角色映射：`\Sent` / 已发送 映射为 `sent`；`Deleted Messages` / `\Trash` 映射为 `trash`；`\Drafts` 映射为 `drafts`；`\All` 映射为 `all`；`\Flagged` / `\Starred` 映射为 `flagged`；
    - 结构节点处理：带有 `\NoSelect` 属性的目录作为 `paused` 结构节点保留，用于树形层级展示，系统不为其排发邮件同步作业；
    - Gmail 虚拟标签优化：针对 `@gmail.com` 及 `@googlemail.com` 账号，其 `\All`（所有邮件）与 `\Important`（重要）标签默认置为 `paused`，消除邮件 2~3 倍重复拉取的存储与 I/O 冗余；针对这些 `paused` 视图发起的显式同步请求在服务端自动归零并以 200 成功响应。
- **分批拉取与瞬态网络重试**：
    - 单次元数据同步任务最大拉取批次限制为 10 页（约 500 封），避免长时间霸占 Worker 队列；
    - 遇到 `TimeoutError`、`SSLEOFError` 等网络瞬态故障时采用指数退避重试，未达重试上限不污染账号为 `failed` 状态。

### 2. Microsoft Graph 同步

- 通过 `/me/mailFolders/inbox` 权威端点解析真实收件箱 ID；
- Delta 增量拉取仅更新本次明确下发的变更字段；若响应中缺省 `isRead` 或 `flag`，数据库严格保留已有状态，不把缺省视为清空；
- 内容字段（主题、摘要、收件人）若显式返回空值，允许清空本地字段。

## 二、 任务调度优先级与连接预算治理

1. **Worker 任务调度优先级分层**：
    为避免大目录同步压制即时交互，队列调度按严格优先级梯度运行（数值越小优先级越高）：
    - **10（最高）**：用户按需触发的即时正文归档任务（去重键 `archive_msg:{id}`）；
    - **40**：出站状态写回操作（已读、星标、移入废纸篓）；
    - **50**：初次账号全量目录扫描；
    - **60**：后台正文归档批次续跑；
    - **75**：文件夹定时增量轮询（设去重键 `delta:{account_id}:{folder_id}`，防止任务堆积）；
    - **80**：定期数据对账检查。
2. **连接池预算控制**：
    - 全局与后台网络连接设有硬性槽位控制，通过 PostgreSQL 会话级 Advisory Lock 协同持有；
    - 容量不足时任务通过 `reschedule_job` 延后执行，不计入失败重试次数。
3. **执行跟踪与孤儿清理**：
    - 同步作业持有唯一的执行代际 UUID，请求通过关联表绑定具体代次；
    - 孤儿任务由后台 Reaper 定期收敛，全量扫描通过 `scan_generation` 防止半扫描引发误删。

## 三、 出站状态写回与安全删除阻断

1. **写回状态机与未收敛意图保护**：
    - 用户标记已读、星标或删除操作先写入本地数据库并入队 `remote_operations`；
    - 入站同步在更新远端元数据前，检查 60 秒写回保护窗口；若本地存在未完成写回操作，入站同步禁止用远端陈旧快照覆盖本地用户的新状态；
    - 写回任务遇到并发或并发限制时自动调度延迟唤醒任务，杜绝空转或遗漏调度。
2. **IMAP 删除安全阻断契约**：
    - IMAP 邮件删除优先调用 `UID MOVE` 移入废纸篓目录；
    - 若服务器不支持 MOVE 或移动失败，**严禁调用全邮箱 `EXPUNGE`，严禁标记 `\Deleted`**，必须 Fail-Closed 向调用方报错，防止用户误清空整个远程邮箱。

## 四、 MIME 归档解析与错误可见性

1. **原文持久化与解析解耦**：
    - 归档调度拉取邮件原始 MIME 数据后，立即写入加密存储；
    - MIME 解析器从原文提取纯文本正文（`text_plain`）、富文本正文（`text_html`）与附件元数据；
    - 若 MIME 解析因损坏、字符集或非标格式报错，系统将原始 MIME 完整保留在存储区，并在数据库记录脱敏的 `MessageBody.parse_error`，不中断同批次合法邮件归档。
2. **前端错误渲染与正文并存**：
    - 阅读器感知到 `parse_error` 时渲染醒目的解析错误横幅；
    - 若解析器在报错的同时提取到了部分可读正文，阅读器在错误横幅下方继续渲染正文，保障用户阅读权益。

## 五、 分块内容寻址与 AES-256-GCM 加密存储

1. **流式分块加密 (`KKMS`)**：
    - 原始邮件 MIME 与独立附件以二进制 Blob 存储；
    - Payload 经分块 AES-256-GCM 加密，并由 SHA-256 计算唯一哈希实现内容寻址与重复数据删除；
    - 支持多版本主密钥轮换。
2. **延迟引用计数与垃圾回收 (GC)**：
    - 存储层同时统计 `MessageBlobLink`（邮件原文）与 `Attachment.blob_id`（独立附件）的引用计数；
    - 执行 GC 物理删除文件前，必须进行数据库事务二次校验；若存在校验异常，立即跳过删除，确保数据零丢失。

## 六、 遗留数据迁移保真契约

1. **历史数据保真导入**：
    - 旧数据库邮件的主题、发件人等空白字段以真实空值导入，不以占位符覆盖；
    - 邮件收发时间仅在提供商显式提供带时区有效时间时迁入，缺失时严格存为 `null`；
    - 缺少远端不可寻址的迁移邮件，`remote_id` 与 `is_archived` 置为 `null`，禁止伪造生成远端 ID。
2. **未知状态可空语义**：
    - 邮件 `is_read`、`is_flagged`、`has_attachments` 采用 nullable 布尔类型贯穿数据库与前后端；
    - 服务商未提供读状态时存为 `null`，不盲目填充 `false`，列表与统计界面保留未知状态展示。

## 七、 收件箱定时轮询调度与增量正文自动存库 (t057)

1. **Worker 周期错峰巡检调度**：
    - Worker 主循环定期执行巡检，对所有启用账号的有效收件箱（`role="inbox"` 且非 paused），按设定期限（默认 1200 秒 / 20 分钟，环境变量 `MAIL_CORE_INBOX_POLL_INTERVAL_S`）检查超期状态；
    - 超期且无在途任务者自动入队 `SYNC_FOLDER_DELTA`，多任务按轮询周期均匀错峰排期（`run_after` 分散），杜绝单点易断的尾递归自调度与瞬时雷暴。
2. **增量收信连带全文存库**：
    - 增量同步拉取新邮件入库后（`upserted > 0`），自动在同事务中入队 `ARCHIVE_MIME_BATCH`；
    - 归档流水线下载原始 MIME 并将解析提取出的 HTML/纯文本直接写入 PostgreSQL `message_bodies` 表，实现全自动收信与具体内容入库。

## 八、 IDLE 监听与全文件夹 STATUS 巡检契约 (t061)

1. **IDLE 唤醒通道**：
    - 每账号至多一条 IDLE 长连接、只 SELECT 收件箱、仅对已完成基线的文件夹建立；服务器未在 CAPABILITY 宣告 IDLE 时不发 IDLE，该账号保持轮询；
    - IDLE 收到变化通知后仅入队 `SYNC_FOLDER_DELTA`（既有去重键 `delta:{account_id}:{folder_id}`），不直接读写邮件数据、不绕基线门禁 / 租约 / fencing；连接在 28 分钟内主动 DONE 重入，断线按指数退避（基数与上限可配）加抖动重连；账号禁用、凭据变更（指纹变化）或收件箱 paused 时立即关闭对应会话；
    - IDLE 长连接使用独立配额（默认 32），不占用 `connection_slots` 任务槽位；持有 IDLE 的账号跳过收件箱周期轮询，让位后恢复。配额席位只按邮件数据排序（2026-10-28 用户拍板，取代原检查点活动时间口径）：主序为账号收件箱内现存邮件的服务器到达时间最大值（IMAP INTERNALDATE，即 `Message.sort_time`，非发件人 Date 头）倒序；收件箱为空的账号整体排在所有非空账号之后，组内依次按其他文件夹邮件到达时间最大值倒序、账号 `created_at` 倒序、账号 id 升序定序。滞回只在同组内按可比到达键生效：挑战者须比最弱在位者新出滞回窗（默认 300 秒）才换人，无可比键时不换人（稳定序），跨组顶替不受滞回保护。
2. **全文件夹 STATUS 巡检**：
    - 覆盖全部非收件箱、非 paused、`sync_enabled` 账号的文件夹；探测为短连接 STATUS（IMAP）或文件夹计数读取（Graph），不做全量 metadata 扫描；
    - 基线快照存 `SyncCheckpoint.cursor.last_status`（总数 / UIDNEXT / 未读 / modseq），无新增迁移；变化判定仅比较基线与探测双方均有值的维度（服务商缺 UIDNEXT 时以总数 / 未读组合判定）；无任何可解析条目的探测按失败处理，不按无变化放行；无变化零入队，变化入队 delta（`priority = 75`）；
    - 单轮探测上限可配，超限按最久未探测优先轮转；未基线文件夹仅记录基线不入队；单夹探测失败隔离并下轮重试；与 IDLE / 轮询的入队共享同一 delta 去重键，收敛幂等。

## 九、 全量基线与日常增量同步边界契约

1. **新账户首次接入强制全量基线**：
    - 新增账户成功后系统自动入队初始同步（`_enqueue_initial_sync` $\\rightarrow$ `SYNC_ACCOUNT_FOLDERS`）；
    - 文件夹发现阶段严格检查 Checkpoint 状态，对无基线或 `full_scan_complete != True` 的目录派发 `SYNC_FOLDER_METADATA` 全量扫描，确保历史邮件完整导入。
2. **所有日常同步接口统一为增量模式**：
    - 设置页「同步全部账户」（`POST /api/accounts/sync-all`）与单账号「立即同步」（`POST /api/accounts/{id}/sync`）创建的 `SyncRequest` 模式严格为 `mode="delta"`；
    - 发现或遍历目录时，对已有基线（`full_scan_complete == True`）的有效文件夹仅排入轻量增量任务 `SYNC_FOLDER_DELTA`，几秒内秒级完成，杜绝日常操作误触全量扫描导致历史重扫风暴及新邮件发现被长时间阻断。
3. **全量重扫严格限定为异常自愈**：
    - 仅在增量同步遇到远端游标彻底失效（`CursorInvalidError`）时，系统才由保护机制清空 Checkpoint 并在隔离控制下启动全量重建，禁止日常常规入口发起非必要的全量历史扫描。
