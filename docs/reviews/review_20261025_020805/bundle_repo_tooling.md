## Strengths

- No shell injection surface anywhere: every subprocess call is argv-list form, git calls consistently use timeouts in the core package (git_ops wraps TimeoutExpired into TaskDataError), and user-controlled identifiers (slug/tid/pNNN/dNNN) are fullmatch-validated before reaching paths or git args in nearly every entry point.
- Ledger and ID allocation are genuinely well built: flock/msvcrt lock held across scan→create and read→append, fail-closed on corrupt ledger lines (refuses to continue rather than risking attempt-number reuse), exact (tid, attempt, execution_id) identity enforced for terminal/report/cleanup/integrate, and best-effort appends are demoted to warnings only for non-authoritative start events.
- Destructive operations are consistently gated: worktree removal checks registered branch ownership and cwd containment, rewind requires interactive/--yes confirmation when commits or dirty state would be lost, purge uses a tombstone + audit-before-delete order, repo_cleanup defaults to dry-run with keep re-checks inside apply_delete, and repo_sync stages per-file rollback backups before overwriting.
- view_server gets the important things right by default: loopback-only bind with an explicit, loudly-warned --allow-non-loopback escape, static-file allowlist, task-doc resolution with is_relative_to containment against allowed roots, and `</script>` escaping for the injected model; board.js renders exclusively via textContent/createTextNode (the single innerHTML use clears a container).
- Atomic-write discipline (tmp + fsync + os.replace, mode preservation) is the shared default via documents.atomic_write_text for front matter, indexes, goal snapshots and prompts; the exceptions found above are localized (repo_sync state, \_id_scan entry creation).
- Instruction surface is more conservative than typical: all skills are disable-model-invocation, task-run explicitly excludes merge from its authorization, sync-core forbids overwriting secrets/host settings and requires approval before commit, template-issue-report mandates redaction before any GitHub issue creation, and reviewer prompts enforce a read-only boundary with anti-self-report evidence rules.
