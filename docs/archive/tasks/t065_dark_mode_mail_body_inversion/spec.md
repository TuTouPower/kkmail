# Task spec

## 背景

当前 kkmail 在深色模式下，若邮件包含显式浅色背景（如写死的 `bgcolor="#ffffff"` 或 `style="background: white"` 等常见 HTML 邮件），前端会将其判定为 `classification = 'light'`，并在深色阅读器容器中渲染为一个白底的「独立纸张卡片」（paper card）。用户反馈即使在深色模式下，大多数邮件正文依然呈现大面积刺眼白色，严重影响暗光环境阅读体验。

参考主流客户端实践（如 Thunderbird 140 的 Dark Message Mode、Outlook.com 智能反转、Apple Mail 以及 DarkReader 核心算法）：

1. 在深色模式下对浅色 HTML 邮件通过 CSS 智能反转（`filter: invert(100%) hue-rotate(180deg)`）将白底翻转为深灰底，并保持超链接等品牌色相；
2. 对图片、视频与 Canvas 元素进行二次反转还原真实画面，并微调透明 PNG 黑色 Logo 的对比度；
3. 为保障极端非标排版的阅读可读性，在阅读器详情工具栏提供单封邮件「开关灯（原色/深色切换）」按钮，并支持在设置中配置默认渲染偏好。

## 契约区

### 范围

- 智能深色正文渲染：
    - 在 `src/frontend/src/lib/mailBody.ts` 中增强深色模式样式注入：深色模式且分类为 `light` 时，默认对 iframe 内部应用智能反转滤镜（`filter: invert(100%) hue-rotate(180deg)`，背景重设为系统深冷青灰色 `#222729`）；
    - 对图片（`img`）、视频（`video`）、画布（`canvas`）与矢量图像（`picture`）二次反转还原色彩，并为可能存在透明底黑色 Logo 的 `img` 增加浅色微阴影保护；
    - 对本身即为暗色背景（`classification === 'dark'`）或未指定背景的纯文本（`classification === 'plain'`）邮件保持现有原生深底渲染，不触发反转。
- 阅读器容器统一：
    - 移除深色模式下浅色 HTML 邮件突兀的纯白外层纸张卡片（`paper-card` 白底），让正文区域与 kkmail 阅读器整体深冷青灰色阶自然融为一体。
- 单信快捷原色切换（逃生通道）：
    - 在 `MessageReader` 顶部详情工具栏新增「原样视图 / 深色视图」切换按钮（日/夜间图标）；
    - 点击可针对当前正在阅读的邮件临时切回发件人原始浅色白底排版；再次点击恢复深色渲染；切换仅影响当前邮件的当前查看视图。
- 本地偏好设置：
    - 在设置面板（`SettingsModal`）增加「邮件正文深色渲染」默认偏好选项（「智能深色」与「保留发件人原始纸张」），选择即时生效并持久化到本地存储。
- 浅色模式保持原样：
    - 系统处于浅色模式时，邮件正文 100% 呈现发件人原始排版，工具栏切换按钮不显示或处于未激活状态。

### 非范围

- 不修改后端存储、MIME 解析或 API 协议，后端存储始终保持原始 MIME 不变。
- 不引入外部重型 JavaScript 运行时脚本注入，保持 iframe 严格沙箱基线（`default-src 'none'`）。
- 不改变字体字号与邮件段落物理排版布局。

### 开源邮件客户端深色模式实现调研与技术对比

针对主流开源邮件客户端对邮件正文深色模式的支持情况与技术实现进行深入调研：

|软件名称|技术栈 / 架构|正文深色支持|核心技术原理|优缺点分析|对 kkmail 的参考结论|
|---|---|---|---|---|---|
|**Cypht**|PHP + Bootswatch (Webmail)|❌ 不支持|仅支持 UI 皮肤级深色（Bootswatch Darkly）。正文由 HTMLPurifier 清洗后直接嵌入 DOM，保留内联样式与白色背景。|正文保持原样白底，深色界面下白块刺眼，割裂感严重。|纯 UI 壳主题无法解决正文白底问题，不可取。|
|**Zero (Mail-0)**|Next.js + Tailwind (Webmail)|❌ 不支持|应用外壳提供深色主题，邮件正文在 iframe 中原样渲染，未对浅色 HTML 作明暗转换。|浅色营销邮件在暗色界面中呈突兀白色卡片。|证实即使是最新开源 AI 邮件客户端，若不对正文作针对性处理仍会有大白块痛点。|
|**SnappyMail**|PHP + JS (Webmail)|⚠️ 部分支持 (可选)|**DOM 样式剥离法**：提供设置项「Remove background and font colors from message body」，清洗时直接剥除 `bgcolor`、`background-color` 与 `color` 等属性，正文回退为客户端默认深底。|优点是不影响图片；缺点是粗暴抹平所有颜色层级，导致警告色、高亮块失效，极易出现文字与局部背景对比度冲突（Issue #1486）。|简单剥除颜色会破坏邮件视觉排版，不应作为默认方案。|
|**Thunderbird**|Gecko (Desktop C++/JS)|✅ 完整支持 (140+)|**DarkReader 动态分析引擎 (`DarkReader.mjs`)**：在阅读端动态遍历 DOM 树与计算样式，算法替换浅底为深色、深字为浅色；并在阅读器工具栏提供**单信「开关灯」快捷切换按钮**。|智能化程度高、图片无反转；但依赖复杂的 JS 样式计算与 DOM 重写，在严格 CSP 隔离下成本较高。|**强烈采纳其交互设计**：在阅读器工具栏提供单信「原样/深色」切换开关作为不可或缺的逃生通道。|
|**Mailspring**|Electron (Desktop JS/C++)|✅ 完整支持|**CSS 智能反转 (Filter Smart Invert)**：在 `email-frame.less` 中对 iframe 施加 `filter: invert(100%) hue-rotate(180deg)`，并对 `img, video, canvas` 施加二次反转恢复原色。|纯 CSS 零 JS 开销，GPU 硬件加速，色相旋转保持品牌超链接原色；但透明底黑色 Logo 反转后会融入深底（需微光阴影补救）。|**强烈采纳其渲染核心**：与 kkmail 沙箱 iframe 架构完美契合，零运行时 JS 损耗，抗内联 `!important` 干扰能力最强。|

#### 对当前 Task (t065) 的架构采纳方案

1. **渲染架构（融合 Mailspring 优势）**：kkmail 邮件正文已运行于独立的 `iframe`（由 `buildMailSrcdoc` 生成），在深色模式且分类为 `light` 时，在内部注入 `filter: invert(100%) hue-rotate(180deg)`，配合图片二次反转与微光投影滤镜（`drop-shadow`），以最小成本实现高保真深色自适应。
2. **交互体验（融合 Thunderbird 优势）**：在 `MessageReader` 详情工具栏增加「太阳/月亮」切换按钮，允许用户随时在深色自适应与发件人原始白底之间无缝切换，彻底解决 1% 极端非标邮件的可读性顾虑。
3. **策略隔离（规避 SnappyMail 缺陷）**：不暴力剥离内联样式，保留完整排版层次；对原生已为暗色（`dark`）或纯文本（`plain`）的邮件前置豁免，避免二次反转变成白色。
