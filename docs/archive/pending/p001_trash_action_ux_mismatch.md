# p001 删除与废纸篓交互用词与无选择时静默无反馈

- 现象：在单封邮件阅读区与列表多选栏中，删除动作的名称和状态反馈割裂。阅读区按钮为 `title="移到废纸篓"`，列表多选栏为 `title="删除所选邮件"`；当用户期望执行删除时，如果误触未多选状态的工具栏按钮，系统由于 `selectedIds` 为空直接静默 return，没有任何提示；单封邮件删除后右侧阅读区未自动重置空态，导致旧上下文残留。
- 影响：用户无法明确感知删除操作是否触发，自动化测试与辅助屏幕阅读器在寻找“删除”按钮时容易产生歧义与定位失败。
- 根因：`MessageReader.tsx` 与 `MessageList.tsx` 针对同一业务动作（移动至废纸篓）使用了不同的属性标签（`移到废纸篓` vs `删除所选`）；批量操作栏在无选择项时未提供明确 disabled 或引导状态；单封删除完成只移除了缓存项，未同步重置 `selectedKey`。
- 同类位点：标星切换（`标记邮件` / `取消标记`）与标已读（`标为已读` / `全部已读`）的用词一致性。
- 测试缺口：现有单元测试直接调用 mock 函数或断言单个按钮存在，未验证无选中项时的边界交互及单封删除后的右侧状态重置。应在组件测试与 E2E 测试补充单封删除后的选区联动断言。
- 线索：`.scratch/bug_repro/` 中端到端自动化脚本点击选择器错位及删除残留复现。
