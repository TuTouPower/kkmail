# 测试工程、隔离机制与质量保障技术规范 (Testing & Quality Specification)

本文档定义 kkmail 测试架构、数据库隔离策略、真实协议验证与自动化质量保障技术规范。

______________________________________________________________________

## 一、 质量原则与测试分层

kkmail 坚持高保真自动化测试架构，严禁使用虚假 Mock 掩盖业务逻辑：

1. **测试必须触达生产逻辑**：
    - 核心业务流程必须由生产代码实际执行；不得用外层虚拟事务 rollback 掩盖跨连接死锁、LISTEN/NOTIFY 广播及并发锁竞争。
2. **测试分层与定位**：
    - **快速单元测试 (Unit Tests)**：覆盖纯逻辑、协议报头解析、URL 校验与 DTO 转换，无外部服务依赖，秒级反馈；
    - **数据库集成测试 (DB Integration)**：基于专用 PostgreSQL 容器，覆盖真实的 SQL 执行、行级锁、Alembic 迁移与 Outbox 队列；
    - **端到端测试 (E2E Tests)**：基于真实 FastAPI + PostgreSQL + Dovecot IMAP + React SPA 驱动 Playwright，验证跨层链路。

## 二、 PostgreSQL 测试环境与实例隔离

1. **专用测试服务与所有权校验**：
    - 本地数据库测试必须连接专用的测试 PG 服务，每轮套件分配独立的数据库名与产物目录；
    - 执行测试前必须校验容器标识、PG cluster、所有者角色及数据库注释；若无法验证所有权或缺少测试密码，拒绝执行写入，杜绝误操作业务数据库。
2. **资源生命周期与确定性清理**：
    - 正常完成、断言失败与捕获到的中断信号（SIGINT/SIGTERM）仅清理本轮分配的数据库与临时目录；
    - 强行终止（SIGKILL）保留带 UUID 标识的记录，下次启动支持精确回收清理，禁止使用模糊前缀批量扫描删除未知数据库。

## 三、 用例级状态隔离与事务收敛

1. **状态污染阻断**：
    - 逐个测试用例执行独立的 Alembic 迁移从空库建表；用例提交的真实 commit 不得残留至下一个用例；
    - 用例结束后强制回收 Worker 线程、数据库连接池、LISTEN 连接与全局 Monkeypatch 替身；清理失败时立即熔断停止后续测试。
2. **确定性测试数据集 (Deterministic Fixtures)**：
    - 采用确定性随机 Seed 生成多账号、中文 multipart MIME、重复 Message-ID、乱序收发时间与加密附件夹具；
    - 确保分页、排序与增量拉取在不同运行轮次下百分之百可重放。

______________________________________________________________________

## 四、 测试执行套件与验证规范

1. **官方测试执行入口**：
    - 后端统一使用 `scripts/run-mail-core-tests.sh` 脚本驱动；
    - 支持 `unit`（快速单元模式）、`run`（完整数据库测试）与 `cleanup`（资源清理）指令。
2. **报告与覆盖率要求**：
    - 完整测试报告输出实际执行用例数、明确跳过原因与未执行清单；
    - 记录核心生产模块（`sync`、`mail`、`security`、`blobs`）的行覆盖率与分支覆盖率。
