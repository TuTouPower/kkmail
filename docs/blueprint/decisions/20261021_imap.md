# 010 IMAP 删除安全阻断策略（2026-10-21）

- **背景**：部分旧 IMAP 服务器缺少 `UID MOVE` 或 `UIDPLUS` 能力，旧代码回退执行 `STORE \Deleted` + `EXPUNGE`，RFC 3501 规定其清空当前目录下全部待删除邮件，造成连带误删风险。
- **决策**：执行绝对安全策略——优先调用 `UID MOVE` 移入废纸篓；若不支持或移动失败，**严禁调用全邮箱 `c.expunge()`，且不要打 `\Deleted` 标记，直接向调用方报错返回失败**（提示当前 IMAP 服务器不支持安全删除）。
- **结果**：100% 杜绝因其他客户端打标未清空而造成的连带误删。
