# Task spec

## 背景

t057 建立的 Worker 周期巡检只覆盖收件箱（`role="inbox"`）；其 spec 非范围明确把非收件箱文件夹排除在自动扫描之外、留给「用户导航按需触发」。但 19bc2b76 已把客户端触发同步整体移除——打开、导航、聚焦都不再触发同步，于是非收件箱文件夹（已发送、草稿、垃圾箱、自定义文件夹及他端客户端的归档目标等）目前没有任何周期发现通道：他端在这些文件夹里的新建、移动、删除只能等账号级发现运行或设置页手动同步时被顺带 delta 才收敛，延迟不可预期。2026-10-28 的同类产品拉取策略对比显示，主流客户端对非收件箱的通行解法是廉价 STATUS 探测全覆盖（Thunderbird 定时 STATUS 探测、Mailspring 每 2 分钟浅扫全部文件夹、SnappyMail 每轮轮转探测）：STATUS 一次短连接即可拿到文件夹总数 / 未读 / UIDNEXT，没变化就跳过，变化才做增量。本 task 把 t057 巡检从收件箱扩展为全部文件夹的 STATUS 探测巡检，补上这个盲区；分钟级即可，不追求实时（实时由 t059 的 IDLE 只负责收件箱）。

## 契约区

### 范围

- 扩展 Worker 周期巡检调度（t057 建立的调度器）：巡检对象从收件箱扩展为全部启用账号（`sync_enabled=true`）的全部非 paused、可选择文件夹；收件箱仍由 t057 既有超期逻辑直接入队 delta，本 task 的探测巡检覆盖其余文件夹（收件箱可同时被探测，但不得与 t057 入队产生重复任务，去重键保证合并）。
- 每轮巡检对目标文件夹执行一次廉价探测：IMAP 用 `STATUS`（`MESSAGES` / `UIDNEXT` / `UNSEEN`，服务器支持时含 `HIGHESTMODSEQ`）经短连接完成，不 SELECT、不 FETCH 内容；探测方式经 provider 能力抽象接入，不支持廉价探测的 provider 维持现状行为（跳过探测，不强制改变）。
- 变化判定与入队：探测结果与本地保存的文件夹状态基线（总数 / UIDNEXT / 未读 / modseq）比对；无变化的文件夹不产生任何任务与内容拉取；有变化的文件夹入队既有 `SYNC_FOLDER_DELTA` 走既有管线收敛，并更新本地状态基线。
- 错峰与轮转：多账号多文件夹的探测在巡检周期内错峰平摊；单轮探测的文件夹数设上限，超出时按最久未探测优先轮转，保证任一文件夹的连续未探测时长不超过可配置上限。
- 排除规则与既有口径完全一致：paused 文件夹（`\Noselect` 结构节点、远端已消失、Gmail 虚拟标签等）、`sync_enabled=false` 账号一律跳过，不产生连接与任务。
- 巡检周期、单轮探测上限、未探测时长上限纳入 t058 集中式配置可调；探测巡检提供独立开关，关闭后行为回到 t057 的仅收件箱巡检。

### 非范围

- 不为任何文件夹引入 IDLE 或其他推送机制（收件箱实时归 t059）。
- 不改变 t057 收件箱巡检的触发与错峰语义。
- 不复活任何客户端触发同步（19bc2b76 的移除结论不变）。
- 不由巡检触发全量 metadata 扫描：无基线文件夹的基线建立仍只归账号发现与手动同步路径。
- 不改变 delta / reconcile 的既有语义、删除防误删门禁与写回保护窗。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：Worker 周期巡检覆盖全部启用账号的全部非 paused 可选择文件夹（含已发送、草稿、垃圾箱与自定义文件夹），按配置周期（默认 1200 秒）对每个文件夹执行探测。
- [ ] AC-002：探测结果（总数 / UIDNEXT / 未读 / modseq）与本地状态基线一致的文件夹，不产生任何 `SYNC_FOLDER_DELTA` 任务与内容拉取，仅消耗一次 STATUS 级探测。
- [ ] AC-003：探测发现变化（新邮件到达、他端删除或移动、未读数变化）的文件夹被入队 `SYNC_FOLDER_DELTA`，并在该轮巡检后经既有管线完成增量收敛落库。
- [ ] AC-004：paused 文件夹、`\Noselect` 结构节点、远端已消失文件夹与 `sync_enabled=false` 账号在巡检中一律跳过，不产生外部连接与任务。
- [ ] AC-005：无基线（`full_scan_complete` 不为真）的文件夹不被巡检探测触发全量 metadata 扫描；巡检对这类文件夹至多探测并记录状态，基线建立路径不变。
- [ ] AC-006：多账号多文件夹的探测时刻在巡检周期内错峰分布；单轮探测文件夹数不超过配置上限，超出时按最久未探测优先轮转，任一文件夹连续未探测时长不超过配置上限（默认不超过 2 个巡检周期）。
- [ ] AC-007：单个文件夹探测失败（超时 / 限流 / 服务器异常）不中断整轮巡检、不把所属账号误标 failed，该文件夹在后续周期自动重新探测。
- [ ] AC-008：巡检周期、单轮探测上限、未探测时长上限与探测巡检开关纳入集中式配置（t058 体系）可调；关闭探测巡检开关后，行为与 t057 落地后的仅收件箱巡检完全一致。
- [ ] [deploy] AC-009：在真实账号部署环境实测：用另一客户端向某非收件箱文件夹移动入一封邮件并删除另一封，一个巡检周期内本地库与远端收敛一致。

## 上下文区

- 来源：用户确认的同步策略对比结论（2026-10-28，五家开源邮件应用拉取策略与 kkmail 对比）；直接动因是 t057 非范围与 19bc2b76 移除客户端触发叠加形成的非收件箱发现盲区

### 有意不测

- 真实服务商的大规模文件夹数（如 300 账号 × 数十文件夹）长周期运行：本地以 mock provider 与 DB 夹具模拟大账号集、文件夹轮转与时间推移验证调度正确性，真实规模经 AC-009 单账号实测与上线后观测覆盖。

### 测试策略

- 单元测试：fake provider 返回可控的 STATUS 探测结果，验证变化判定（总数 / UIDNEXT / 未读 / modseq 各维度）、无变化零入队、轮转与未探测上限、排除规则。
- 集成测试：mock provider + 本地 DB 夹具，验证探测发现变化后 delta 收敛全链路、单夹失败隔离、与 t057 收件箱入队的去重合并。

### 未知契约清单

<!-- 规范（门禁必留，不得删除） -->

未核实的外部契约标为 `UNVERIFIED-BLOCKING` 或 `UNVERIFIED-SPIKE`；核实后改写为结论和验证方式。无则写“无”。

<!-- /规范 -->

- 个别服务商 STATUS 字段缺失（如 Coremail 系不返回 UIDNEXT）：UNVERIFIED-SPIKE，实现期以 fake 响应验证回退判定（以 MESSAGES / UNSEEN 组合变化触发 delta），真实服务商差异经 AC-009 实测核实，不阻断 backlog。
- Microsoft Graph 文件夹廉价探测的可用查询与配额成本：UNVERIFIED-SPIKE，实现期核查 Graph provider 的文件夹计数 / 元数据查询成本；若无廉价探测手段，Graph 账号按本 spec 范围维持现状（跳过探测），不阻断 IMAP 路落地。

### 风险与回退

- 风险：账号与文件夹规模放大后探测连接数上升，与既有 8 槽位连接预算及服务商限流的相互作用；状态基线保存不当导致每轮误判变化、引发 delta 风暴。
- 防御：错峰平摊 + 单轮上限 + 轮转（AC-006）；无变化零入队（AC-002）使稳态成本仅为短连接 STATUS；探测连接同样受全局连接预算治理。
- 回退：集中配置关闭探测巡检开关即回到 t057 仅收件箱巡检；或 git revert 对应 commit。

### 依赖与约束

- 依赖 t057（周期巡检调度，已完成）与 t058（集中式配置，已完成）。
- 必须遵守既有约束：paused 文件夹跳过规则（p060 / A321）、任务去重键合并、checkpoint 写入 fencing。
- 与 t059 同改 Worker 调度与连接面，无硬依赖；排期时由 task-schedule 评估冲突，建议错开执行。
