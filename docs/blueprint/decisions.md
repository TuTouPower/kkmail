## 一、 产品边界与长期排除项决策

以下条目已由产品与架构方案明确锁定，确认为当前阶段不予处理或超出产品范围的设计：

1. **单用户能力凭据模型 (Single-user & Capability-based UUID)**：完整授权定义见 [docs/guides/security.md](../guides/security.md)「授权模型」。

2. **永久废弃浏览器扩展 (No browser extension - wontfix)**：

    - **裁决**：永久不发布浏览器扩展；原 `browser-extension/` 目录与 `/api/extension/*` 桥接已彻底废弃并移除，禁止重新引入。

3. **移除多皮肤系统 (No system skins)**：

    - **裁决**：彻底移除 Flask 时期的外部皮肤包与模板系统（`data/skins/` 目录）；外观严格限定为 SPA 内置的亮色、暗色及跟随系统主题。

4. **产品不含发信与联系人 (No sending & contacts)**：

    - **裁决**：产品核心聚焦于收信与多账号聚合阅读，明确不包含撰写 (compose)、回复 (reply)、转发 (forward)、联系人管理及发信系统通知；前端 SPA 不提供写信界面。

5. **平台打包未签名维持现状 (Desktop packaging signature & notarization)**：

    - **裁决**：macOS (dmg) 与 Windows (nsis) 当前为自托管未签名构建，暂不实施商业代码签名、公证及应用商店上架适配，维持当前打包现状。

6. **支持真实入库文件夹与收藏分类只读浏览 (Folder navigation, t008 替代原暂缓决策)**：

    - **裁决**：开放收藏六大分类（收件/未读/已发/草稿/废纸篓/垃圾邮件）与账号真实入库文件夹只读浏览；支持精确 `folder_id` 与标准角色分页检索，保持不实现归档动作与跨目录移动。
    - **决策原因与暗坑**：
        1. **数据源约束**：侧栏文件夹仅来源于已入库且 Provider 实际同步的文件夹，不凭空捏造目录，Gmail 标签不伪造成“归档”目录；
        2. **去重保证**：跨标签或多位置邮件在角色聚合与分页中去重，每封邮件单次呈现；
        3. **只读边界**：不引入跨目录移动或归档写回动作，保留既有 Trash 删除与已读/旗标标记。

7. **暂不开发归档与跨目录移动 (Archive, junk and move)**：

    - **裁决**：维持当前仅支持废纸篓/删除（Trash，本地优先 + 异步远程入队）的现状，暂不开发归档 (Archive)、垃圾邮件 (Junk) 及跨文件夹移动 (Move)。
    - **决策原因与暗坑**：
        1. **异构 Provider 语义根本性冲突**：Gmail 的归档与移动实质是“打/剥离标签”（无物理移动）；Graph 移动邮件后其远程 `message_id` 会发生改变；IMAP 移动邮件则会彻底销毁旧 UID 并分配新 UID，且大量私有邮件服务商缺失标准的 `\Archive` 特殊文件夹；
        2. **增量同步状态断裂风险**：远端 ID/UID 的突变若处理不慎，极易导致增量同步将其误判为全新邮件重复拉取，或残留幽灵本地数据。

## 二、 架构演进与安全技术决策

### 2026-10-25: 会话 epoch 使用短时进程内缓存

- **背景**：`read_session` 每次认证请求都查询 PostgreSQL，持续增加数据库负载。
- **决策**：每个进程缓存 session epoch 5 秒。当前进程内的改密与登出在数据库提交后立即刷新缓存；其他进程发起的吊销最迟在 TTL 到期后生效。缓存过期后数据库不可用时继续 fail closed。
- **安全边界**：跨进程吊销存在最长 5 秒传播延迟；本进程发起的吊销不等待 TTL。该决策覆盖 2026-10-21 决策中“跨进程即时吊销”的时效要求，数据库仍是 epoch 权威源。

### 2026-10-23: 写回批次自动续跑与本地字段意图收敛保护（t012）

- **背景**：此前批次尾部使用同键入队被运行中的 claimed 任务去重吞掉，导致超过 20 条操作中断；旧同步快照覆盖本地读状态；且 autoflush=False 导致统计读取早于 ORM flush。
- **决策**：
    1. claimed 任务捕获后续唤醒并在 complete 后原子派生新 pending 任务，保证批次自然排空；
    2. 入站同步基于 RemoteOperation 待处理状态及 60 秒写回完成保护窗口仲裁，保护本地未收敛意图不被旧快照覆盖；
    3. 文件夹统计计算前强制 flush 会话，杜绝 SQL 聚合与 ORM 状态顺序漂移。

### 2026-10-22: 持续集成 (CI) 分层门禁与发布边界隔离（t023）

- **决策**：创建只读权限的 GitHub Actions 工作流（`ci.yml` 和 `scheduled.yml`），禁止工作流申请写发布/镜像/标签权限；
- **分层**：
    1. PR 与 Push 必跑门禁：模板契约、前端全套（lint/type/unit/OpenAPI/build/轻量UI冒烟）、桌面（基础单测+严格打包冒烟）、后端全量（真实 PostgreSQL + Dovecot IMAP，0 跳过）以及真实全栈端到端测试；
    2. 定时与手动扩展演练：真实跨库恢复演练、三版本历史数据平滑升级迁移、多进程 Worker 故障恢复、确定性大邮箱基准与资源测量；
- **环境隔离**：CI 与本地环境共享统一的运行时与命令入口，并行测试任务使用独立数据库与隔离目录，退出时严格清理，杜绝跨任务污染。
- **状态变更注记（2026-10-27 补）**：本条已被本地门禁决策取代，不再是现行决策。GitHub Actions 工作流已于 2026-10-26 在提交 `49a6d024` 移除，现行口径以 [testing.md](testing.md)「无远程 CI」为准：仓库不运行 GitHub Actions 远程 CI，测试门禁由开发者在本地执行。本条仅作历史记录保留。

### 2026-10-22: 专用 PostgreSQL 测试生命周期（t013）

- **决策**：本地复用固定测试容器，每轮建立独立测试库；CI 使用一次性隔离容器。不复用业务 PostgreSQL、密码或卷。
- **保护**：销毁前同时验证专用容器、PG cluster identity、数据库所有权标记和仓库运行记录；不得仅凭库名前缀判断可删除。
- **状态**：runtime 安全保护与 t014 测试隔离已验证；最终两个固定 seed 完整数据库套件均通过，仍有两项真实 IMAP 测试待 t016 启用协议服务。

### 2026-10-21: 方案 A - 认证密码与会话状态统一入库

- **背景**：此前 Compose 部署修改密码仅修改进程内存缓存，容器重启后回退至环境变量旧密码；且会话版本号在多进程模式下无法共享。
- **决策**：创建 `auth_credentials` 表（迁移 `20261021_0012` 与 `0013`），将登录密码 bcrypt hash 与全局 `session_epoch` 统一持久化至 PostgreSQL。
- **结果**：环境变量仅作为全新安装首启的 bootstrap 数据源；一旦数据库初始化完成，密码以数据库为权威源，API 改密直接写库，彻底解决重启回退问题；改密与登出跨进程即时吊销旧 Session。

### 2026-10-21: IMAP 删除安全阻断策略

- **背景**：部分旧 IMAP 服务器缺少 `UID MOVE` 或 `UIDPLUS` 能力，旧代码回退执行 `STORE \Deleted` + `EXPUNGE`，RFC 3501 规定其清空当前目录下全部待删除邮件，造成连带误删风险。
- **决策**：执行绝对安全策略——优先调用 `UID MOVE` 移入废纸篓；若不支持或移动失败，**严禁调用全邮箱 `c.expunge()`，且不要打 `\Deleted` 标记，直接向调用方报错返回失败**（提示当前 IMAP 服务器不支持安全删除）。
- **结果**：100% 杜绝因其他客户端打标未清空而造成的连带误删。

### 2026-10-21: 历史泄露凭据资产处置

- **背景**：公开历史 commit `[REDACTED_HISTORICAL_COMMIT]` 遗留 Outlook 账号密码与 Token。
- **决策**：经溯源确认为上游原仓库 `assast/outlookEmail`（作者 `luekongbai`）在 2026-01-13 的首个初始化提交，系上游原作者历史测试资产。本仓库不执行破坏性 Git 历史重写（避免 fork 分叉与破坏下游 clone），在安全审计基线中将其标记为上游遗留已知资产，并指导外部撤销。

### 2026-10-21: 前端长列表游标分页与未读角标

- **背景**：此前 SPA 列表硬编码仅展示 100 封，侧边栏角标直接基于本地缓存第一页推导，超出 100 封时未读数少报。
- **决策**：
    1. 后端提供 `/api/mail/stats` 全局未读聚合端点，侧边栏单次请求直接读取全局及各账户真实未读计数；
    2. 邮件列表迁移为 TanStack React Query 的 `useInfiniteQuery`，结合后端的 Keyset 游标分页提供“加载更多”按钮，实现深翻页；
    3. 重构缓存更新器以同时适配普通数组与 `InfiniteData` 结构，彻底解决删除邮件导致的列表归零闪烁问题。

### 2026-10-22: 深色正文保守适配及固定浅色富文本独立纸张方案 (t006)

- **背景**：深色模式下邮件阅读区若无差别涂黑或强制滤镜反色，极易破坏第三方富文本排版和图表对比度；若全局保留白底，又会在深黑窗口中呈现刺眼通栏白块。
- **决策**：
    1. **保守分类**：通过 DOM 属性与样式解析区分无显式配色（plain）、显式浅色富文本（light）与显式深色（dark）；
    2. **无显式配色与纯文本**：深色模式下直接继承深色底色 `#1A1A1C` 与高对比白字 `#FFFFFF`，链接使用 `#0A84FF`；
    3. **固定浅色富文本**：深色模式下以独立居中纸张卡片（`.mail-paper-card`，白底、8px 圆角、16px 内边距与柔和阴影）呈现，外层阅读容器保持 `#1A1A1C`，消除通栏刺眼白块并 100% 保护富文本原文可读性；
    4. **安全红线不变**：严禁通过放宽 DOMPurify 的 script/style/meta 规则或 iframe 边界达成主题适配；拦截远程图片默认行为与 CSP 沙箱严格保持。

### 2026-10-23: MIME 解析错误持久化与前端可见报错边界 (t026)

- **背景**：此前归档正文解析异常有静默回退，报头异常仅记 debug；详情 API 已返回 parse_error 但前端转换丢弃，MessageReader 将解析失败误判为“尚未完成同步或内容为空”。用户澄清历史乱码已手动修复，要求任何解析错误直接在前端明确报错。
- **决策**：
    1. **不做历史乱码推测修复**：不新增推测性自愈或数据迁移，读取时不扫描或篡改历史字段；
    2. **原文保存与解析结果分离**：保存 raw MIME 到 BlobStore 确保数据可恢复性；正文/报头/附件名解析失败记录脱敏 `MessageBody.parse_error` 并跳过派生落库，同批合法邮件不阻断；
    3. **前端明确展示错误**：`mailCoreToMailDetail` 保留 `parse_error`；`MessageReader` 检测到错误直接展示“邮件解析失败”与脱敏原因，即使存在摘要或部分内容也绝不伪装成功或误报为空正文；
    4. **状态隔离**：合法空正文与待归档邮件保留原提示；切换邮件即刻清理旧错误，不跨邮件残留。

### 2026-10-23: 用户自定义账号分组与独立侧栏顺序 (t027)

- **背景**：原侧栏把分类入口与账号树组织为个人收藏结构，难以管理多账号；参考 demo 只表达布局，不应缩减现有六类功能或把示例名称固化成产品数据。
- **决策**：
    1. 侧栏采用“所有账号／用户自定义分组／账号列表”三段；六类全局分类继续独立可用，每个分组提供相同分类，账号仍可访问同步到的全部真实文件夹；不预置“工作”“个人”等 demo 分组。
    2. 账号保持单组归属；分组顺序、账号总列表顺序与组内顺序由服务端持久化。默认账号顺序按不区分大小写的邮箱域名及完整邮箱地址升序。
    3. 完整侧栏布局通过一个 API 事务验证并保存，避免归属与排序半更新；移组后邮件范围按最新成员关系解析，空组 fail-closed。
    4. 拖拽来源列表决定语义：主列表内重排不清除分组归属；组间拖拽更新归属；移动端继续提供设置中的分组选择入口。
