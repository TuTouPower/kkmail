# 需求规格：测试隔离与质量验证

## 背景

测试必须实际执行生产路径，保护业务数据，区分快速单元、真实集成与尚未执行行为，不以静默 skip 或覆盖率数字冒充验收。

## 契约区

### 范围

- 专用 PostgreSQL 测试服务、每轮独立数据库和资源所有权验证。
- 后端逐用例数据库/进程状态隔离、确定性人工邮件数据、可重放乱序及生产模块行/分支报告。

### 非范围

- 业务数据库和真实邮箱操作。
- 用 Mock 替代所有数据库写入，或用外层 rollback 掩盖跨连接提交、锁与通知。

### 验收标准

- [x] AC-001：本地测试复用专用服务，每轮分配不同数据库与产物目录；必须验证容器、PG cluster、数据库 owner role/comment 和仓库运行记录，不凭库名前缀删除。
- [x] AC-002：正常结束、失败和可捕获中断只清理本轮资源；强制终止保留可辨认记录，按确切 UUID 恢复清理，不扫描删除未知库或停止其他运行。
- [x] AC-003：缺少操作者提供的测试密码或无法证明数据库所有权时拒绝测试写入；直接 pytest 同样保护，URL 查询参数覆盖目标被拒绝。
- [x] AC-004：完整数据库测试经生产 Alembic 从空库建表，PG 条件 skip 必须失败；快速模式明确报告未运行 DB 套件。
- [x] AC-005：用例真实 commit 不进入下一用例初态，Worker/LISTEN/checkout 连接和全局替身在正常及断言失败后恢复；清理失败立即停止后续用例。
- [x] AC-006：确定 seed 的多账号、空目录、中文 multipart MIME、重复 Message-ID、固定排序时间与加密附件数据可重放，生产分页无重无漏。
- [x] AC-007：完整后端套件在两个固定 seed 连续运行通过，报告实际执行、跳过原因、未执行清单及生产模块行/分支覆盖。

### 可测试性声明

全部 AC 可自动测试；真实环境结果必须留证，不用模拟结果替代真实 PG 验证。

## 上下文区

### 有意不测

- 本阶段两项真实 IMAP 测试因专用服务未启动而跳过；由 t016 接续，不能计为真实协议通过。

### 测试策略

- 使用 `scripts/run-mail-core-tests.sh` 的 start/run/unit/cleanup/stop 入口。
- 真实专用 PG 验证独立库、双仓库并存、哨兵保护、失败/中断清理及 SIGKILL 恢复。
- 使用实际双连接 commit、SKIP LOCKED/fencing、事务性 NOTIFY、API lifespan 和 Worker；禁用通知的隔离变异必须失败。
- seed 41、17 完整套件各 352 passed / 2 IMAP skipped，快速套件 252 passed / 102 skipped；完整记录与命令见 `docs/blueprint/testing.md`。

### 未知契约清单

无。

### 风险与回退

- 数据库、连接和进程身份混淆会造成误删除或跨用例污染；所有权不明时失败关闭，清理异常停止套件。
- 回退对应实现 commit；不回收业务数据、未知测试库或其他运行资源。

### 依赖与约束

- 依赖 Docker、仓库 `.venv` 和操作者提供的专用测试随机密码。依赖安装与测试执行分开。
- 产物只写当前仓库 `.scratch/`；测试密码使用忽略文件或环境变量，不入库。
