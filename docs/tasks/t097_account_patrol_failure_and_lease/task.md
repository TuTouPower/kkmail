# Task spec

## 背景

全夹巡检按目录遍历，只缓存构建成功的 Provider。构建失败走目录探测失败路径，普通配置异常因此会反复构建并写目录状态。基于 `060e0893` 的复现使用真实 Provider 构建逻辑和替身 DB 会话，一个缺少 IMAP 凭据引用的账号有三个目录，产生三次构建、三次目录写入调用及零次 STATUS。现有半开抢占比对冷却值，结算清理仅检查键存在，无法识别已过期的持有者。

## 契约区

### 范围

- 将 Provider 构建结果按账号处理，保留文件夹轮转和探测预算。账号级构建失败与实际目录探测分别结算。永久认证失败沿用凭据失效，后台传输失败沿用健康隔离。
- 将巡检冷却与半开租约放入独立账号巡检运行状态。使用唯一租约标识约束结算，允许到期重领。通过 Alembic 一次迁移可解析的旧冷却时间并移除 `Account.config` 中旧键。
- 巡检自己拥有的事务只覆盖短时 DB 操作。并发配置编辑、单目录失败、冷却与恢复继续遵循各自的作用域。

### 非范围

- Worker 连通性复核、前台同步行为、IDLE 资源管理和迁移执行器。

- [x] AC-001：同轮选中同账号多个文件夹时，Provider 最多构建一次。缺少 IMAP 凭据引用等构建失败只产生一次账号失败结算，STATUS 调用和目录状态写入均为零，其他账号继续巡检。
- [x] AC-002：实际目录探测遇到首个账号级认证或传输故障，只有该探测更新目录状态和目录失败数。兄弟目录无探测，既有 `last_probe_at`、`last_probe_failures` 保持原值，缺失行保持缺失。永久认证失败使凭据失效，后台传输失败保持连接健康状态。单目录异常仅影响该目录。
- [x] AC-003：冷却期内复扫计入跳过，零探测、零目录写入，前台同步仍可执行。过期后并行巡检只有一个有效持有者。过期持有者的晚到结果无法清除或覆盖新租约，当前持有者成功时清除冷却。
- [x] AC-004：存量可解析冷却时间在升级后继续生效，原账号配置的其余字段和值完整保留。新巡检状态只通过新存储生效，升级后旧键已移除。
- [x] AC-005：生产巡检入口的只读事务和半开认领事务均在 Provider 构建及 STATUS 网络调用前结束，巡检期间提交的账号配置编辑可正常保存。

### 风险与回退

- 风险：状态迁移可能改变存量冷却时长，过期结果可能覆盖当前租约。以真实 PostgreSQL 验证存量值和交错提交。
