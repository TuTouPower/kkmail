# 20261128 增量水位权威与瞬态队列生命周期

## 背景

生产单机库在仅 22,095 封邮件下出现 `worker_jobs` 84,199 次全表顺序扫描、76.6 亿累计返回元组、双份等价 `from_text` GIN 三元组索引，以及终态任务与已发布 outbox 默认 7 天保留导致的近 168 MB 热表驻留。根因不是索引缺失，而是同一事实存在两个权威源：周期收件箱调度既读 `SyncCheckpoint.updated_at`，又扫描 `worker_jobs` 终态行取 `max()` 兜底；瞬态队列表被当成审计归档保留；字段改名迁移遗留重复索引。

## 决策

1. **同步水位收口到检查点**：`sync_checkpoints.last_delta_settled_at` 是周期 delta 调度的唯一水位，表示"最近一次 delta 执行链结算时间"。结算语义明确：成功链耗尽、跳过（基线缺失/禁用同步）、重试耗尽的终态失败推进水位；续页、限流、容量延期、失锁、游标失效转重建等中间态不推进。推进采用单调语义（GREATEST），过期执行即便晚提交也不能回退水位。周期调度不再读取 `worker_jobs` 终态历史。

2. **三状态首次排期**：无完整基线或重建中不排 delta，由元数据发现链建立基线；基线就绪且水位为 NULL 立即到期首次同步；水位已置按轮询间隔判定。

3. **瞬态队列短保留与回收资格**：终态 `worker_jobs` 与已发布 `outbox` 默认保留 24h（代码常量，无产品级开关）。回收仅删除已发布连续前缀并原子推进 `pruned_through_seq`，SSE/分发落后窗口触发 `resync`。终态任务若其 link 仍关联未结算的同步请求目标则暂不回收，避免重聚合丢失失败结果。

4. **索引与统计契约**：新增 `(updated_at) WHERE status IN ('done','failed')` 部分索引支撑清理；删除重复 `ix_message_search_from_trgm`，仅保留 ORM 声明的唯一索引；大批量回收后按需 `ANALYZE`，日常短 delta 不重复刷新统计。

5. **升级迁移**：`20261128_0008` 新增水位列并以 `updated_at` 回填既有行（保守：最多重扫一次，绝不漏同步），删除冗余索引，校准统计；`downgrade` 可逆。

## 影响

- `CURRENT_HEAD_REVISION` 推进至 `20261128_0008`。
- 语义失效的旧测试（无基线账号期望被周期调度、冗余索引存在断言）按 TDD 规则整体重写并注明理由，未就地篡改正确断言。
- 与 t095（单机运行时资源收敛）共同修改 Worker 运行入口与关联 spec，按章节归属协调写域，顺序执行时补组合回归。
