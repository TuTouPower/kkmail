# 002 保留 Blob 私有权限并以宿主导出替代宿主 UID 备份 (t075)（2026-11-05）

- **背景**：部署备份进程为写入宿主 `0700` 目录被切成宿主 UID，却又要读取应用 UID 所有的 `0600` blob，单个进程被迫同时适配两个数据所有者；历史提交 `77622a45` 与 `4c00620f` 只在两个方向来回调整。
- **决策**：保留 blob `0600`、私有目录 `0700` 的私有存储契约；备份容器以应用 UID 运行、blob 只读、在容器私有目录生成密封包；宿主通过 Docker CLI/API 导出到宿主所有的 `0700` staging，校验归属和包完整性后原子发布；恢复以目标应用 UID 显式创建私有目录与文件。存量权限通过显式维护命令归一化，不使用全局 `0644` 或启动时递归修补。
- **原因**：密文不是放宽权限的充分理由；`0644` 还会因 `0700` 父目录而无法解决遍历问题，并依赖 umask/宿主环境。把身份切换留在宿主导出边界，既保持最小权限，又让备份与恢复各自只面对一个数据所有者。
- **回退**：保留旧备份包与 rollback 镜像；导出/校验失败时不发布半成品；权限归一化只改 owner/mode、不改文件内容，可按维护流程回退。
