# 014 MIME 解析错误持久化与前端可见报错边界 (t026)（2026-10-23）

- **背景**：此前归档正文解析异常有静默回退，报头异常仅记 debug；详情 API 已返回 parse_error 但前端转换丢弃，MessageReader 将解析失败误判为“尚未完成同步或内容为空”。用户澄清历史乱码已手动修复，要求任何解析错误直接在前端明确报错。
- **决策**：
    1. **不做历史乱码推测修复**：不新增推测性自愈或数据迁移，读取时不扫描或篡改历史字段；
    2. **原文保存与解析结果分离**：保存 raw MIME 到 BlobStore 确保数据可恢复性；正文/报头/附件名解析失败记录脱敏 `MessageBody.parse_error` 并跳过派生落库，同批合法邮件不阻断；
    3. **前端明确展示错误**：`mailCoreToMailDetail` 保留 `parse_error`；`MessageReader` 检测到错误直接展示“邮件解析失败”与脱敏原因，即使存在摘要或部分内容也绝不伪装成功或误报为空正文；
    4. **状态隔离**：合法空正文与待归档邮件保留原提示；切换邮件即刻清理旧错误，不跨邮件残留。
