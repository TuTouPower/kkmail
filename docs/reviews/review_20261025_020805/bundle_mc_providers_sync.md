## Strengths

- IMAP remote_ids are namespaced as UIDVALIDITY␟folder␟UID (imap.py), eliminating the classic cross-folder UID collision, and UIDVALIDITY changes raise CursorInvalidError for a controlled rebuild instead of silent corruption.
- TLS is the default for IMAP with ssl.create_default_context() (cert + hostname verification, satisfying AC-001), the password field is repr-masked, and OAuth access tokens are never logged.
- OAuth token URIs are checked against an HTTPS host-prefix allowlist that resists userinfo/suffix spoofing, BearerTransport refuses cross-origin token use (protecting server-supplied Graph delta/next links), and missing expires_at forces a refresh rather than trusting a token forever.
- SSRF defense on IMAP hosts fails closed on mixed DNS answers; error surfaces consistently pass through safe_provider_summary/safe_error redaction.
- Sync writes are fencing-gated inside the committing transaction (assert_fencing uses FOR UPDATE on the lease row), checkpoints commit atomically with message writes, and deletions are only ever applied from explicit delta @removed/history events or post-full-scan reconcile — never inferred from partial pages.
- Partial-update fidelity is taken seriously: supplied_fields projections in metadata/delta application preserve unknown read/flag/attachment state (AC-011/012/027/028), and unconverged local intents override remote flag echoes.
- IMAP MOVE/TRASH never falls back to \\Deleted + mailbox-wide EXPUNGE (AC-002), and Graph trash never falls back to hard DELETE on 5xx/403/429 — only on 404.

## Spec compliance

- AC-001 (TLS default + mailbox quoting): substantially met — TLS default and quoting are implemented; the explicit plaintext opt-out (finding 1) and missing CR/LF stripping in quoting (finding at imap.py:196) are the residual gaps.
- AC-002 (UID MOVE or error, never EXPUNGE): met in imap.py apply_remote_operation for both move and trash.
- AC-003 (Graph inbox via /me/mailFolders/inbox + recursion): met in graph.py list_folders, including the AC-032 rule that a same-named user folder does not become a second inbox when the canonical id is known.
- AC-004 (Gmail historyTypes + hydration): met — repeated historyTypes are sent via doseq encoding and upserts are hydrated with messages.get; the hydration failure mode (High finding at gmail.py:236) is a robustness gap, not a contract violation.
- AC-011/AC-027/AC-028 (partial delta fidelity + in-page coalescing order): mostly met via supplied_fields; residual gaps are the meta-only is_flagged coalesce drop (delta.py:123) and \_minimal_meta's complete-snapshot claim (gmail_history.py:48).
