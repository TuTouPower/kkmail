# Task spec

## 背景

启动与离线工具已共享迁移规划器，但各自控制只读检查连接、写入分派和错误处理。t096 解决了启动路径的事务锁重叠。基于 `060e0893` 的真实 PostgreSQL 定向验证已跑通旧 `0030` 迁移；现有检查连接回归只观测空库的 `idle in transaction`，既有回滚注入用普通 `RuntimeError`。

## 契约区

### 范围

- 由同一执行器管理检查、释放只读连接和执行写计划。CLI 启动、`--migrate-only`、`--check-migrations` 与离线工具交付各自模式和空库策略。
- 复用只读连接管理器及共享规划器。检查返回独立于连接的计划，写阶段显式分派。窄转换继续在写事务内加锁重验。
- 补齐 PostgreSQL 连接生命周期、受支持旧库漂移拒绝与写事务回滚验证，修正水位回填测试中 `Sent` 目录的 `sent` 角色。

### 非范围

- 已支持版本名单、历史 Alembic revision、新 schema 需求和 Worker 启动模式。

- [ ] AC-001：空库通过启动或 `--migrate-only` 初始化到当前 head，离线工具按既有契约拒绝空库。受支持旧库经实际写路径升级到 head 并通过 schema 校验。已知较旧 Alembic revision 可继续增量升级。
- [ ] AC-002：在进入空库写升级及受支持 LEGACY 窄转换时，参与该次只读检查的事务均已结束，物理连接均已关闭。LEGACY 转换后的实际 Alembic 升级也能完成。
- [ ] AC-003：在可升级的库上运行 `--check-migrations` 或离线 dry-run 只执行检查。受支持旧库出现 schema 漂移时，启动和离线入口均明确拒绝，schema、版本和业务数据与调用前相同。
- [ ] AC-004：窄转换已执行部分写入后触发 `SchemaValidationError`，转换事务全部回滚。检查 schema、版本及代表性业务数据与调用前一致，Alembic 升级尚未开始。移除注入故障后可正常重试，已成功转换的数据库重跑保持数据一致。

### 有意不测

- 历史已不支持的版本以拒绝用例覆盖，不需要历史发布环境。

### 测试策略

- 在专用真实 PostgreSQL 测试库中记录本次检查连接的 backend PID。从独立观测连接查询 `pg_stat_activity`，在首个写入口确认目标检查 PID 已退出。
- 复用受支持 LEGACY 夹具，覆盖预检漂移、写事务内故障、完整快照比较、重试及真实升级。套件设置有限等待，锁回归应明确失败。
- 复跑启动、离线 dry-run、Alembic schema 一致性与水位回填门禁。若其他 task 同时新增 revision，使用集成后的当前 head 复验。

### 风险与回退

- 风险：统一入口可能改变空库策略或将只读锁延伸到写阶段。以双入口、只读模式和真实 PG 连接回归覆盖。
- 回退：回退实现 commit 恢复入口编排。已经按既有 Alembic 链升级的数据保留当前版本；数据恢复按已验证备份流程执行。

### 依赖与约束

- 无硬依赖。t098 若并行修改 `__main__.py`，集成后同时复验启动模式与迁移入口。
