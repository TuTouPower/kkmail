# Task spec

## 背景

调整 kkmail UI 时，纯自然语言难以精确指认控件，截图标注成本高。用户于 2026-10-22 批准仅交付“稳定编号 → 复制引用 → 搜索源码”闭环，快捷键确认为 Windows/Linux `Ctrl + Shift + .`、macOS `⌘ + Shift + .`。

## 契约区

### 范围

- 为登录、侧栏、邮件列表、邮件详情、设置中可独立修改的控件、标题、静态说明、空状态和错误提示分配固定编号；列表行及其主题、发件人、摘要、时间等区域按渲染模板编号。
- 通过已确认快捷键切换编号模式，显示当前可见元素标签；点击标签复制引用，按 `Esc` 退出。刷新后默认关闭。
- 编号即源码检索入口；固定编号以 `data-ui="ML03"` 形式显式声明，采用 SB（侧栏）、ML（列表）、MR（详情）、ST（设置）、LG（登录）前缀加数字。编号与 DOM 顺序、文案、业务状态和数据主键解耦。
- 复制纯文本引用包含编号、开发者定义区域及元素说明，供用户补充修改要求。提供简短使用与源码检索说明。

### 非范围

- 自动截图、AI 连接、自动修改代码、内置源码浏览器、文件跳转协议及源码路径/行号映射。
- 重复列表的实例编号、邮件或账号 UUID 映射、历史引用数据库、独立编号注册服务。
- 设置页新增开关、移动端专用入口、快捷键自定义、模式持久化、后端 API 或 DB 变更。
- 给全部 DOM 节点、装饰图标编号；进入邮件 HTML iframe 为正文内容编号；给 Electron 原生窗口或系统菜单编号。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：页面加载及刷新后默认不显示编号；Windows/Linux `Ctrl + Shift + .`、macOS `⌘ + Shift + .` 可在登录页和登录后界面开启/关闭编号模式；输入框聚焦时仍可切换，长按按键不反复切换，退出不改输入值。
- [ ] AC-002：编号模式覆盖范围所列五个分区中当前可见目标；隐藏或已移除元素无标签，可见禁用控件仍可引用。开启模式前后原页面元素位置、尺寸不变。
- [ ] AC-003：同一 UI 目标在主题切换、宽度变化、刷新、相邻控件增删及状态文案变化后保留编号；不同模板目标不共用编号。重复邮件行或账号行中同一模板目标共用编号，不以行顺序或业务主键生成新编号。
- [ ] AC-004：切换页面、滚动容器、调整列宽、打开侧栏或右键菜单后，标签仍对应当前可见目标，不留下旧标签；窄窗口中标签可读且不落到视口之外。
- [ ] AC-005：点击标签成功时，剪贴板文本包含对应固定编号、区域及元素静态说明，并给出成功反馈；同一模板不同实例复制相同引用。复制不可用或被拒绝时明确提示失败，不显示成功。
- [ ] AC-006：点击编号不会触发目标业务操作；编号模式下点击原控件仍保留原行为；关闭模式后恢复原键盘行为。`Esc` 在模式开启时只退出编号模式，不同时关闭设置、侧栏或右键菜单。
- [ ] AC-007：任取一个展示或复制出的编号，可用仓库文本搜索定位唯一目标模板的显式编号声明；无需运行应用、生成索引、读取 source map 或 React 内部结构。使用说明包含实际可执行的 `rg` 检索示例。
- [ ] AC-008：复制引用不包含运行时邮箱、邮件主题、正文、输入值或凭据；邮件正文仅引用 iframe 外层容器，原有沙箱及过滤行为保持有效。

## 上下文区

- 来源：无外部条目。2026-10-22 当前会话中用户明确批准创建 task，并限定为稳定编号、复制引用、搜索源码；此前已确认快捷键。

### 有意不测

- 邮件协议、后端同步、Electron 原生菜单和系统全局热键：本 task 不改变这些路径；快捷键在应用网页获得焦点时生效。
- 邮件正文内部排版和逐节点编号：不进入邮件 HTML iframe，仅验证正文容器可引用及现有安全边界未变。

### 测试策略

- 按项目 TDD 约定先补充失败测试，再实现；测试触达生产编号模式和实际页面标记，不仅测试替身。
- 组件测试覆盖平台修饰键、自动重复按键、输入聚焦、Esc 消费顺序、固定编号状态切换、复制成功/拒绝及静态文本边界。
- 源码扫描覆盖固定编号声明唯一性及重复列表模板复用；从实际编号执行 `rg -n 'data-ui="ML03"' src/frontend/src` 等检索，示例编号以最终实际标记为准。
- 在 `tests/e2e/` 使用现有 Playwright 测试设施，验证登录、主界面、设置、右键菜单、滚动、列宽变化和窄视口的标签定位，及点击编号不执行删除/同步等业务操作。
- 执行前端 `npm test`、`npm run lint`、`npm run build` 与相关 E2E；完整门禁遵循 `docs/blueprint/testing.md`。

### 风险与回退

- 风险：右键菜单、滚动容器及响应式隐藏元素可能导致标签错位；已有多个 `Esc` 监听可能同时响应；大量邮件节点可能增加观察成本。覆盖层仅开启时工作，并合并位置更新。
- 风险：快捷键可能被浏览器、系统或扩展拦截；实施期验证当前浏览器与 Electron 交付环境，出现冲突先报告，不擅自更换已批准快捷键。
- 回退：关闭编号模式立即移除标签与监听；无需数据迁移。尚未合入时在 task 分支修复；合入后需撤回时单独回退本 task 实现，不覆盖其他 task 改动。

### 依赖与约束

- 无硬前置依赖。纯前端交付，浏览器和 Electron 网页共用实现，不新增依赖或后端持久化。
- 已有 `App.tsx`、`SettingsModal.tsx`、`MessageList.tsx` 分别处理侧栏、设置和右键菜单的 `Esc`，必须验证事件优先级。
- 已核实 `main.tsx` 为统一入口，`App.tsx` 包含登录与主界面分支；邮件 HTML 仍经 `lib/mailBody.ts` 过滤并在无脚本 iframe 中展示。
- t006（active）、t009、t010 涉及相邻前端布局或设置区域；存在文件重叠，建议串行实施，执行前按有效状态重新核对。此处为调度建议，不建立功能硬依赖。
- 新普通文件及目录使用 snake_case；沿用现有设计 tokens，不改变邮件业务逻辑。
