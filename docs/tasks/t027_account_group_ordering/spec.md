# Task spec

## 背景

现有 Account.group_id 为单组归属，AccountGroup 已有 sort_order；API 只有创建/删除分组与单账号归属更新，缺少重命名、排序写入及账号独立排序。v3 需要后端持久保存组织状态，使网页与桌面使用同一事实源。

## 契约区

### 范围

- 补齐分组重命名、分组顺序、账号总列表顺序、组内账号顺序及默认排序恢复接口。
- 复用现有单组归属，支持移入、跨组、移出；需要同时移动与排序时作为单次事务提交。
- 补齐排序模式与顺序持久化，更新 Alembic、OpenAPI 与前端生成类型；为后续 UI 提供类型化 API。

### 非范围

- 不实现侧栏 UI、拖拽、分组邮件检索。
- 不引入多组归属、嵌套分组或远端邮箱目录变更。

### 验收标准

<!-- 规范（门禁必留，不得删除） -->

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：分组支持创建、重命名和删除；名称 trim 后不能为空、沿用 128 字符上限与唯一名称约束；空白、重名和不存在目标均返回可识别错误且不产生部分写入。
- [ ] AC-002：删除含账号分组后，仅清空其账号归属；账号、凭据、邮件、附件与总列表顺序保持；从独立数据库会话读取可确认结果。
- [ ] AC-003：账号可从无组移入、从 A 组移到 B 组或清空归属；最多属于一个分组，目标不存在时整体失败。
- [ ] AC-004：默认账号排序按大小写不敏感邮箱域名升序，再按完整邮箱地址升序；总列表与各组独立切换至手动顺序，重新请求与服务重启后保留。
- [ ] AC-005：总列表排序不修改账号归属或任何组内顺序；组内排序不修改总列表顺序；跨组移动在一个事务内更新归属和目标位置，无重复、遗漏或中间状态。
- [ ] AC-006：自定义分组可调整顺序且重启后保留；新增分组追加末尾。恢复默认排序同时恢复总列表及所有组内账号的域名排序，不改分组先后与账号归属；手动列表新增/移入账号默认追加末尾，显式指定位置除外。
- [ ] AC-007：重复、遗漏、外组账号或不存在 ID 的排序载荷被整体拒绝；并发组织写入后每个已提交快照仍符合单组归属及排序完整性，冲突有明确处理且无半次写入。
- [ ] AC-008：空库升级、旧库升级及最新迁移降级再升级成功，已有账号与分组归属不变；旧库账号初始化为默认排序，旧分组相对顺序保留；API 经认证/CSRF 保护并与生成类型一致。

### 风险与回退

- 风险：排序与归属分开写会出现半状态；新增字段初始化可能改变旧数据可见顺序。
- 回退：回退本 task 执行提交；仅在隔离库演练迁移降级。生产迁移前验证备份可恢复；未经批准不在业务库执行迁移或删除数据。

### 依赖与约束

- 无前置 task；复用 src/mail_core/accounts/service.py、mail/application/accounts.py 与 api/accounts.py。
- 排序与归属是实例级组织数据，服务端持久化；折叠与主题仍属本地 UI 偏好。
- API 端点名称及最小存储结构在执行期确定，遵循现有分层；不提供过时路径兼容层。
