# Task spec

## 背景

邮件详情 To 为空时，阅读器把用户账号邮箱当作邮件收件人显示，无 To 或 Bcc-only 邮件因此被错误描述。

## 契约区

### 范围

- 只展示邮件详情实际提供的 To 地址；缺失时明确呈现空/未提供状态。
- 账号邮箱继续作为账号归属信息，不混入邮件报头。
- 增加空 To、有效 To、Bcc-only/导入缺失 To 的组件测试。

### 非范围

- 不改服务端收件人解析、邮件导入或 Bcc 存储。

### 验收标准

- [ ] AC-001：详情 To 为空时不显示账号邮箱或其他推测地址；账号归属位置仍显示实际账号。
- [ ] AC-002：详情 To 非空时仅显示 API 提供值，多收件人与无 To fixture 均有自动化覆盖。
- [ ] AC-003：切换邮件后不把前一封的收件人带到当前邮件。

## 上下文区

- 来源：2026-10-23 MessageReader 审查：`detail?.to || selected.to || account.email` 混合邮件收件人与账号归属。

### 有意不测

- 不测试服务商是否允许读取 Bcc；只验证 API 已提供值的展示。

### 测试策略

- 组件测试输入 To、空 To、账号邮箱和连续邮件切换，断言不展示推测地址；运行 MessageReader 与全量前端门禁。

### 风险与回退

- 风险：空 To 留白可能被误认作加载问题。
- 回退：显示明确“未提供”提示，不回退账号邮箱。

### 依赖与约束

- 不改变邮件 API；账号邮箱与 To 字段语义分离。
