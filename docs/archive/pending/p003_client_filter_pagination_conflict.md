# p003 客户端纯内存过滤与游标分页冲突导致已标记Tab显示空屏

- 现象：当当前加载的邮件页面（前 100 封）中全部为未标星邮件时，点击列表顶部的“已标记”过滤 Tab，邮件列表直接变为 0 封并展示“没有邮件”，即使用户数据库中存在标星邮件（位于后序页中）也无法展现。
- 影响：用户无法查看所有已标记邮件，误以为星标功能损坏或星标邮件已丢失，破坏了标签筛选的核心价值。
- 根因：`MessageList.tsx` 中的“未读”与“已标记”筛选依然停留在前端内存过滤（`raw.filter(m => listFilter === 'flagged' && !m.is_flagged ? false : true)`），未能将 `is_flagged=true` 或 `is_read=false` 过滤参数下推至后端的 `/api/mail/inbox` 数据库查询接口。当某单页拉取的邮件不包含匹配项时，内存过滤直接抹杀所有结果，造成空屏。
- 同类位点：未读邮件筛选（`listFilter === 'unread'`）在首屏无未读、深页有未读时的同类空屏风险。
- 测试缺口：现有组件测试使用小规模假数据（首屏即包含各种状态邮件），未构造“第一页全为普通邮件、第二页全为星标邮件”的翻页场景。应在前端与端到端测试补充下推过滤参数后的多页过滤断言。
- 线索：端到端实测点击“已标记”Tab 时，由于首屏 100 封均为导入的无星标邮件，控制台直接打印 `Flagged rows count: 0`。
