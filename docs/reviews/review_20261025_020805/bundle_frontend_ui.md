## Strengths

- Mail HTML security is done properly (spec AC-005): MessageReader renders the body only via an iframe with `sandbox={MAIL_IFRAME_SANDBOX}` = `allow-popups allow-popups-to-escape-sandbox` (no allow-scripts, no allow-same-origin), `referrerPolicy="no-referrer"`, a srcdoc built by DOMPurify sanitization plus an in-frame CSP (`default-src 'none'`), and remote images blocked by default with a per-message opt-in that resets on message switch. No `dangerouslySetInnerHTML` anywhere in the unit (grep-verified).
- theme_bootstrap.js is injection-safe: it whitelists the stored preference to exactly 'dark'|'light'|'system' before touching `dataset.theme`, wraps localStorage/JSON.parse in try/catch, and never writes untrusted strings into the DOM.
- Credential hygiene in the account form: mailbox password and OAuth client_secret/refresh_token use type="password" with autoComplete="new-password"/"off" as appropriate, credentials are never re-displayed when editing ("留空保持不变"), the OAuth popup is opened with `opened.opener = null`, and the device-code UI exposes only the short user code.
- Native `<dialog>` usage in settings_account_form/credential_help restores focus to the invoking control on close and traps focus via showModal; SettingsModal and Sidebar both surface query errors with working retry buttons and use aria-live/role=alert for async feedback.
- ErrorBoundary offers inline per-pane recovery (重试模块 without a full reload) plus a copyable diagnostics report with copied/failed feedback states.
