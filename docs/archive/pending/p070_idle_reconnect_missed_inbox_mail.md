# p070 IDLE 断线重连后不补偿同步，收件箱新邮件可无限期不入库

- 现象：2026-10-31 用户报告 OpenCode 收据邮件（INTERNALDATE `2026-10-31T08:05:19Z`，即本地 16:05:19）直到本地 20:10:57 才出现在数据库。数据库 `messages.created_at = 2026-10-31 12:10:57.518+00`，此前唯一的收件箱自动 delta 是 16:00:55–16:01:35；16:05 之后到 20:10:47 没有任何自动 `SYNC_FOLDER_DELTA`。20:10:47 的 `sync_requests.trigger=manual`（`2dcc95a5-fa38-4d77-b622-51ad2686b68d`）才把该邮件拉入库。期间 Worker 仍在运行（19:27–19:34 仍有其他文件夹任务），19:43:54 容器重建后也没有补拉。
- 影响：所有 IMAP 且持有 IDLE 席位的账号。IDLE 连接断线/主动重连/Worker 重启期间到达的收件箱邮件不会被发现，且账号重新进入 `held/idling` 后 t057 轮询继续跳过它，导致静默无限期滞后；只有后续另一次 IDLE 变化事件或用户手动同步才会收敛。收据/验证码等时效邮件可能长时间不可见。已扫描同类位点：仅 IMAP IDLE 路径存在该缺口；Graph 账号走 t057 轮询，有 20 分钟上限；文件夹 STATUS 巡检明确排除 inbox（`src/mail_core/sync/patrol.py:117`），不构成收件箱兜底。
- 根因：`IdleWatcherManager._watch_loop` 在连接断开后重建会话，`ImapProvider.open_idle_session` 的 `SELECT INBOX`（`src/mail_core/providers/imap.py:1731`）只取当前 EXISTS/UIDNEXT 快照，IDLE 只上报订阅之后的新变化；代码在成功建连后直接 `_set_state(watch, "idling")`（`src/mail_core/sync/idle_watcher.py:494`），从不入队补偿 delta。断线窗口内已到达的邮件因此永远不会产生 IDLE 事件；同时 `schedule_periodic_inbox_sync` 对 `held_idle_account_ids()` 中的账号直接跳过（`src/mail_core/worker/main.py:234-237`），于是既无事件也无轮询。`wait_for_change` 的 `timeout` 分支只重入 IDLE（同一连接），同样不核对服务端 `UIDNEXT`/EXISTS 与本地检查点。`.scratch/repro_idle_reconnect_gap.py` 用假会话复现：断线后重建会话并进入 held/idling，`_enqueue_delta` 调用数为 0。
- 测试缺口：`tests/mail_core/test_t061_idle_watcher.py::test_ac003_manager_recovers_after_disconnect` 只断言会话被重建并回到 held/idling，没有断言重连后入队补偿 delta，等于把缺陷行为固化为预期。`test_ac005_held_accounts_skip_inbox_polling` 只验证跳过轮询，没有验证 held 账号仍有收敛通道。应补：1) watcher 层测试——首次建连与每次断线重连各入队一次 `SYNC_FOLDER_DELTA`（同 dedupe key 合并，不产生重复执行）；2) 假 IMAP 服务器测试——建连后断开期间 EXISTS 增加，重连必须触发补偿；3) 结合 `schedule_periodic_inbox_sync` 断言 held 状态下即使轮询跳过，补偿任务仍能覆盖断线窗口内到达的邮件。
- 线索：`.scratch/repro_idle_reconnect_gap.py`（现存最小复现：`PYTHONPATH=src .venv/bin/python .scratch/repro_idle_reconnect_gap.py`）；生产数据：`messages.id=668406d2-b10d-49fb-9b7e-03eb8b846e55`，`worker_jobs.dedupe_key=delta:09242245-62e9-4ce9-962f-2c4f845cb014:c198d81a-7dd7-49fb-b323-099e9398b525`；`worker:idle_state` 中该账号状态为 `idling`。
