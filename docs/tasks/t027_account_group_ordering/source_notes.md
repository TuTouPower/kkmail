## 本批 task 采用的明确取舍

- 继续单组归属，不引入多组关联；总列表展示全部账号，组视图只引用成员。
- 分组、归属与排序存服务端，网页/桌面共用；主题及展开折叠存本地偏好。这是基于双端共用同一后端的设计选择，聊天只要求持久保留，并未指定存储层。
- 总列表与组内账号顺序独立。总列表内拖动只排序；从组拖回总列表才解除归属。原型 `drop` 分支仅看 `groupId` 时会在总列表重排中清除已有归属，本批以用户“同列表排序、跨列表移组”的意图为准，不复制该分支。
- 账号/分组标题点击与箭头均控制展开；邮件视图由子项进入。账号展开状态按账号 ID 共用，组自身折叠独立。
- 未读沿原型取 inbox 未读；“垃圾箱”取 `trash`，产品显示“废纸篓”避免与 `junk` 混淆。
- 原型四类快捷入口作为导航骨架；保留当前已同步的已发、junk、归档和自定义真实目录浏览。不存在的远端目录不伪造；真实文件夹只显示一次。
- 恢复默认排序只恢复各账号列表的域名排序，不重置分组顺序或成员关系。新增分组追加末尾；手动模式新增账号默认追加，明确落点则按落点插入。
- 分组搜索维持当前跨文件夹搜索语义，只缩小账号集合，不额外扩大为搜索算法改造。分组全部已读仍按当前角色/旗标范围执行，不宣称只作用于搜索结果。
- 真实平台识别使用已有受控 preload；不把 demo 的 `?shell=desktop`、假红绿灯或 600px 断点带入产品。继续使用 760px。
- demo 中写邮件、回复、转发、归档动作不纳入本批；项目已锁定这些边界。正文安全沙箱、账号凭据流程、现有图标偏好继续复用。
