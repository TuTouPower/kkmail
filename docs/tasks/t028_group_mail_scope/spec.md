# Task spec

## 背景

当前邮件 HTTP API 仅接收 account_id，领域查询已有 account_ids 聚合入口。分组导航不能仅把若干账号首屏拼接，否则会破坏统一分页、搜索与批量已读范围；尤其现有 account_ids 空集合可能被当作全账号。

## 契约区

### 范围

- 让收件/未读/已发/废纸篓列表、全文搜索、统计和全部标记已读接受明确分组范围。
- 按当前服务端成员关系解析分组，保持 keyset 去重、排序、搜索翻页与既有已读写回。
- 更新 OpenAPI、生成类型及前端类型化请求方法；后续组件接入由 t029 负责。

### 非范围

- 不做侧栏界面、分组 CRUD 或账号排序。
- 不改变现有搜索跨文件夹语义、搜索匹配算法、远端协议与正文解析。

### 验收标准

- [ ] AC-001：指定存在分组后，inbox/sent/trash 角色列表和 inbox 未读筛选仅返回当前组员邮件；其他组与无组账号不混入；同封邮件多位置仍只返回一次。
- [ ] AC-002：组内两账号有相同排序时间且邮件超过一页时，升序与降序逐页遍历均不重复、不遗漏；空分组列表、搜索与统计为空或零，全部已读影响零封，绝不回退全账号。
- [ ] AC-003：搜索保留现有匹配与 offset 翻页语义，但结果与 total 严格限于组员；组内收件总数、未读数可由完整服务端数据准确获得，不依赖已加载邮件页。
- [ ] AC-004：分组全部已读仅影响组员中当前角色和旗标筛选匹配邮件，并沿用远端写回状态机；组外及不匹配邮件保持原状。
- [ ] AC-005：不存在或已删除分组返回明确不存在错误；分组参数与 account_id 或 folder_id 同时提交时拒绝歧义请求，不静默扩大范围；不传任何范围参数才表示全局。
- [ ] AC-006：账号移入/移出或分组删除后，下一次请求按最新已提交成员关系解析；不存在旧成员持久快照或因过时 cursor/offset 混入组外邮件；成员变化后前端应从首屏重查。
- [ ] AC-007：不带分组参数时，全局、单账号及精确 folder_id 的原有列表、搜索与已读范围行为继续通过已有测试；新增契约经认证/CSRF 与生成类型校验。

- demo 的发信、回复、转发与归档动作：不属本次侧栏改造及项目当前产品范围。

### 测试策略

- 真实 PG 构造两个组、无组账号、空组、相同时间和多位置邮件；通过 HTTP 验证列表/搜索/统计/全部已读，检查写回队列。
- 重点测试空 account_ids 与 None 区分、非法组合、组删除及成员变更后的连续请求；执行 scripts/run-mail-core-tests.sh run 和前端 API 契约测试。

### 风险与回退

- 风险：空分组被解释为全量、批量已读越界、搜索或计数遗漏分组条件。
- 回退：回退本 task 执行提交；没有业务数据删除，验证产生的数据只在隔离测试库销毁。

### 依赖与约束

- 无新 task 硬依赖；现有 Account.group_id 足以解析成员。
- 复用 mail/application/queries.py 及既有搜索/统计/已读服务；不在前端 fan-out 多账号邮件后拼接。
- 未读定义为 inbox 内未读；原型“垃圾箱”对应 trash（废纸篓），不等于 junk（垃圾邮件）。
