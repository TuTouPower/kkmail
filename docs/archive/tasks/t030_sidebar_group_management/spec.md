# Task spec

## 背景

设置页已有创建/删除分组，缺少重命名及账号归属操作。v3 将常用操作放在侧栏，同时需要在触摸或键盘环境提供无需拖动的账号移动方式。

## 契约区

### 范围

- 账号列表右侧用文件夹加号新建分组，分组行菜单提供重命名/删除。
- 账号管理提供单组选择和不加入分组，侧栏与设置复用同一组织命令及缓存失效行为。
- 复用现有真实账号添加流程和主题设置，不复制 demo 的仅填邮箱假账号流程。

### 非范围

- 不实现拖拽或重新设计整个设置页；不提供删除账号的新快捷方式。
- 不新增账户认证协议、发信、联系人或远端目录管理。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

- [ ] AC-001：账号列表行右侧显示文件夹加号控件，具备“新建分组”可访问名称；不会被解释或执行为新增账号，提交后新组出现在顶层且列表更新。
- [ ] AC-002：分组菜单提供重命名及删除；重命名后导航标题和设置名称更新；名称校验与 t027 一致，取消不写入，错误保留输入并可重试，进行中不重复提交。
- [ ] AC-003：删除前明确提示只移除分组、保留账号和邮件；确认后组消失、账号仍在总列表、当前已删除组视图回到所有收件箱；取消保持原状。
- [ ] AC-004：账号管理下拉选择当前组、其他组或不加入分组；保存后总列表和组内列表、角标与当前组邮件范围更新，失败显示明确错误并恢复服务端事实，无需刷新页面。
- [ ] AC-005：已有设置创建/删除入口与侧栏采用同一服务端结果及失效规则，不遗留旧组名、旧账号归属或重复创建；真实账号添加与深浅/跟随系统主题仍可用。
- [ ] AC-006：菜单和对话框支持键盘进入、Escape/取消关闭、焦点返回触发点；普通 HTML 文本显示组名，特殊字符不变成 HTML；窄屏可完成账号移组，不依赖拖动。
- [ ] AC-007：分组名称与归属选项仅来自服务端已有数据及用户输入，支持任意合法组名；不预置“工作”“个人”等示例分组，不按示例名称设置专用行为；无分组时显示空列表和创建入口。

- 组件测试覆盖创建/重命名/删除与取消、重复提交、API 失败、输入转义、焦点恢复和设置联动。

### 风险与回退

- 风险：多个入口缓存失效不一致或删除文案让用户误以为删除账号。
- 回退：回退本 task 执行提交；分组及账号归属数据仍由已有服务端 API 读取，不删除业务数据。

### 依赖与约束

- 依赖 t029（其包含 t027、t028 前置）；复用组织 API、现有 SettingsModal 与 apiRequest 的 CSRF。
- 不在设置外暴露凭据；不改变现有账号删除授权与确认。
