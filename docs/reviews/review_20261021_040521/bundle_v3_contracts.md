## Spec Compliance

- 生产元数据 → MIME → 正文/附件 → FTS 合同缺失；现有组件/应用测试通过手工 DB seed 证明“可读”，不能证明“可产生”。
- Graph v1.0 folder DTO 与 fixture DTO 不相符；Gmail History stub 与 fixture full metadata 不相符；需要协议真实形态 fixture。
- 单用户 UUID 即能力、仅 inbox UI、SPA 首100条、无发送/联系人/通知/浏览器扩展，均按既定产品范围处理，未当缺陷。
- DB 列/索引与当前 0001–0009 迁移链已静态核对；未发现足以单列的 migration column mismatch。FTS generated document 是迁移特定列，未直接按 ORM 未映射认定运行时故障。
- desktop source/sidecar/frontend/resource 路径静态对应；Linux scaffold soft-ok、macOS/Windows 需要预置 PostgreSQL 为已明确的当前限制，未另报发布失败。

## Strengths

- HTTP DTO 从 OpenAPI 生成到 TS，别名层薄；列表/详情 adapter 使用同一生成模型。
- 写请求集中到 client.ts，CSRF 与统一错误解析；read/flag request body 必填。
- Provider、应用查询、存储模型明确分层；checkpoint 与数据写入同事务并有 fencing。
- attachment UUID-only 下载和 streaming MIME/blob 合同明确，未将路径权限与多租户权限混淆。
